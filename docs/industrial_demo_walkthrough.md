# 泵站维护知识构建：网页人工测试指南

这套材料将北辰泵站设备台账及配套实例约定为本项目的专家基准。
目标是体验完整流程：本体 → 权威来源 → 专家实例 → 普通文档抽取 →
自动消歧 → 人工审核 → 发布 → 溯源检索。

本轮服务入口：<http://127.0.0.1:8002/playground>。
这是加载本次修改的独立本地服务；原有 8000 / 8001 服务及数据保留。
本轮自动验收使用 Tenant Beta，Tenant Alpha 留给人工从头执行。
如果服务已停止，在项目根目录运行：

```sh
PLAYGROUND_BOLT_PORT=17694 ./scripts/run_playground.sh --port 8002 --no-open
```

启动会重新建立临时数据库并加载 120 个基线 Chunks。关闭启动进程会清理
该临时数据库；本指南中的源文件和模板保存在仓库中，可以重新执行。

## 先准备材料

点击顶部“知识构建”。页面上方新增“泵站维护示例包”，每份材料都可以
“下载文件”，也可以使用以下仓库文件：

| 文件 | 用途 | 预期大小 |
| --- | --- | --- |
| [authoritative_source.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/authoritative_source.txt) | 专家基准来源：泵站、设备、机械密封、设备编码、额定功率及关系 | 309 字符 / 1 Chunk |
| [maintenance_report.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/maintenance_report.txt) | 普通业务文档：同一设备、部件与新增渗漏风险 | 153 字符 / 1 Chunk |
| [homonym_report.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/homonym_report.txt) | 可选反例：同名但设备编码不同的泵 | 151 字符 / 1 Chunk |

首次测试保持文件原样。网页会验证权威来源的精确字节摘要，然后把实际
入库返回的文档、版本和 Chunk ID 填入实例模板；修改原文后，原实例坐标
不再适用，不会自动套用。

## 1. 选择治理身份

在右上“当前治理身份”选择 **Tenant Alpha · Finance + Legal**。
它具备本体管理、构建、导入、审核、发布、质量审计和文档生命周期权限。
所有本轮文档的访问组都只勾选 **alpha-finance**，保持一致。

切换身份会清除已生成的实例草稿及消歧结果。建议先做完主流程，再做权限测试。

## 2. 发布本体（01）

1. 在示例包点击“载入示例本体到 01”。
2. 查看 JSON：key 是 `pump-maintenance-demo`，version 是 `1`。
3. 找到 Equipment：`EquipmentCode` 是 STRING 身份属性，`RatedPower`
   是以 kW 表示的 DECIMAL 属性。设备名称相同不等于设备身份相同。
4. 点击“导入为草稿”，在新出现的版本卡片点击“发布此版本”。

检查点：该本体状态为 **PUBLISHED**。载入模板本身不会执行导入或发布。
如果以前已经完成此步，点击“刷新版本”检查现有同 key 版本即可，不要反复
导入旧版本。最好从本轮为你保留的 Alpha 环境开始。

## 3. 将权威来源仅入库（03）

1. 在示例包“权威来源文档”卡片点击“填写上传信息到 03”。
2. 在 03 选择刚下载的 `authoritative_source.txt`。
3. 标题、来源 URI、来源名称、语言、本体 key 已填好；访问组只选
   `alpha-finance`。
4. 确认“构建方式”为“仅切块与向量化（权威来源，不调用抽取模型）”。
5. 点击“上传、切块并向量化（不抽取）”，等待完成。

检查点：结果为 **SOURCE_ONLY**、**1 Chunk**；实体和断言候选均为 0。
这一步仍会调用 Embedding 服务，但不会调用 LLM 抽取。09 中能看到该文档。

02 的实例 JSON 此时会自动填入真实的 Document / Version / Chunk ID。
这只是表单预填，实例还没有导入或发布。如果中途刷新网页丢失预填，使用
同一文件、URI、访问组再次执行仅入库；幂等来源不会多建一份文档。

## 4. 导入并发布专家实例（02 → 05）

1. 回到 02“导入权威 A-Box”，查看刚生成的 JSON。
2. 检查原文引文和字符范围，以及设备编码 `BC-P-101`、功率 `37.5 kW`。
3. 点击“校验并导入权威层”。
4. 到 05，导入返回的 revision IDs 已加入待发布列表。
5. 点击“发布变更集”。

检查点：07“刷新活动清单”应显示 **7 条权威记录**：3 条实体提及、2 条实体
关系和 2 条字面量属性；实体为“北辰水处理一号泵站”“循环水泵”“机械密封”。
关系为 `INSTALLED_AT`、`CONTAINS`，属性为 `EquipmentCode`、`RatedPower`。
它们标记为 **AUTHORITATIVE / EXPERT_IMPORT**。

在 08 点击“运行质量审计（不保存）”，应看到通过。也可以选择
“运行并保存审计”，随后“刷新审计历史”查看不可变记录。

## 5. 上传普通检修报告并抽取（03）

1. 在示例包“普通检修报告”卡片点击“填写上传信息到 03”。
2. 选择 `maintenance_report.txt`，访问组仍只选 `alpha-finance`。
3. 确认构建方式切回“切块、向量化并由 LLM 自动抽取”。
4. 点击“上传、切块、向量化并抽取”，等待任务结束。

检查点：1 Chunk，出现模型候选；04 自动载入审核队列并开始实体匹配。
任务明细可以查看 findings、候选数及是否复用了已完成结果。结果下方的
“首次校验通过”“第二次校验通过”或“校验仍未通过”卡片显示每轮结果。
如果首轮 JSON、结构或证据校验未通过，模型最多有一次根据
具体错误纠正输出的机会；两轮都保留审计。它不会自动批准候选或修改原文。
每次请求最多 4 次模型调用；为预留纠正预算，LLM 模式最多接收 2 Chunks，
仅入库模式最多接收 4 Chunks。每次模型调用仍限 30 秒，整个构建限 90 秒。
本轮原文采用单设备维护条目，设备名只出现一次，后接编码、功率、部件与风险。
这些才是要检查的事实；模型输出仍可能不同，**候选记录数不应作为固定的
模型输出保证**。

如果模型返回空结果、隔离记录或拒绝 findings，应查看并记录实际结果，
不要为了得到预期数量直接批准错误候选。
两轮仍未通过时，拒绝结果会保留；重试同一操作键会复用该任务的终态结果。
新操作键代表另建一次受限任务，不应反复提交来掩盖失败。供应商故障或超时
不会触发这次自动校验纠正，可在
依赖恢复后显式恢复任务，复用已完成的 Chunk。
逐轮摘要展示产生本次终态结果的运行；此前依赖故障运行的完整审计仍保留
在服务端，不会把原始模型响应暴露到网页。
网页收到完成响应（包括 REJECTED）后会清除本次操作键；再次点击上传会
开启新任务。因此看到最终拒绝时应先查看和记录错误，不要连续点击上传。

## 6. 查看自动消歧并确认链接（04）

无需逐条点击“匹配权威实体”；队列载入后最多两个匹配请求并发执行。
查看每条实体提及下方自动显示的“自动消歧建议”：

- **北辰一号循环水泵**：若当前实体提及绑定了完整编码 `BC-P-101` 的属性
  事实，应对应权威实体“循环水泵”，显示匹配建议、身份属性及权威来源证据。
- **BC-P-101机械密封**：应通过唯一治理别名对应“机械密封”。
- **机械密封渗漏风险**：权威层没有该实体，应保留为新的风险实体候选。

当前消歧只采信**绑定到该条 mention revision 的身份属性事实**。同一实体在
长文中多次出现时，某次提及有编码，不代表其他提及自动获得该编码；后者可能
显示身份属性缺失的 CONFLICT。不能因为名字相同，就强行链接或把另一处的
证据套过来。本入门材料避免重复设备提及；复杂长文的身份传播仍需后续设计。

对有充分证据的正确设备和部件匹配，点击“确认链接并批准实体”，输入审核
依据并确认。系统会批准该实体提及，同时重新关联依赖事实；**相关事实仍
待审核**。如模型产生额外提及，逐条核查其身份属性和证据；不要预期每条都能
得到唯一匹配建议。

再批准原文支持的新实体“机械密封渗漏风险”，并逐条核对剩余候选的关系、
编码、功率和证据。风险实体提及与其 `EXPOSED_TO` 关系都需要审核；只批准
关系会缺少可发布的端点。这里还要做一次重复事实整理：

1. 设备链接完成后，模型抽取的 `EquipmentCode = BC-P-101` 和
   `RatedPower = 37.5 kW` 与已有专家事实重复。本体将这两个属性定义为单值；
   当前发布校验按属性断言条数计数，不能把两份相同属性一起发布。
2. 核对权威值及单位确实一致后，对这两条模型属性候选选择“拒绝”。可在自己的
   测试记录中注明“与已发布权威属性重复，保留权威事实及当前来源审计”；当前
   网页普通审核使用固定操作说明，没有自定义说明输入框。这里拒绝的是重复入图，
   原始检修文档和抽取审计仍保留。不要移除专家属性，也不要放宽本体基数。
3. 勾选剩余正确的新风险实体、`CONTAINS` 和 `EXPOSED_TO` 关系，点击
   “批量批准勾选项”。关系保留各自来源证据；不支持的事实应拒绝，暂不能判断
   的记录可以隔离。

不要将不确定的相似匹配直接视作同一设备。若模型属性值与专家值不同，应保留
为待处理冲突，不要按本例将它当作相同的重复事实处理。

检查点：自动匹配没有悄悄修改或发布知识。候选中的模型来源始终保留
**SECONDARY / LLM_EXTRACTED**。相同 revision 的已完成匹配会复用；
“刷新审核队列”和每条“刷新匹配／重新匹配”可以重新计算。
若匹配明确显示依赖错误，先保留候选并查看错误信息；问题恢复后使用该条
“重新匹配”执行只读查询，不要连续重试、改动编码或直接批准来绕过检查。

## 7. 发布审核结果（05 → 07 → 08）

1. 在 05 检查审核通过的 revision IDs，然后点击“发布变更集”。
2. 如果刷新网页后列表为空，点击“刷新可发布候选”，勾选本轮记录。
3. 在 07“刷新活动清单”，分别按权威来源和检修报告的 Document ID 筛选。
4. 在 08 再运行质量审计。

检查点：专家记录仍为 AUTHORITATIVE；模型新增事实为 SECONDARY。
设备和部件对齐到已有实体，新增风险保留独立身份。当前清单中包含原有权威
知识及新发布的检修知识；质量审计通过。审核批准不会自动完成发布。
本轮验收的活动清单为 12 条：7 条权威记录加 5 条次权威记录。这个数量对应
本次抽取的 3 条实体提及、4 条断言及上述去重操作，模型输出不同时应按证据核查。

## 8. 到检索台检查来源与图谱

保持 Alpha · Finance + Legal，点击顶部“检索台”，输入：

> 北辰一号循环水泵的设备编码、额定功率和已记录风险是什么？

点击检索，查看“相关 Chunks”“知识子图”和检索过程：

- 相关原文包含 `BC-P-101`、`37.5 kW`、机械密封渗漏风险。
- 引用指向本轮文件的准确版本、Chunk 和字符位置。
- 已发布子图可展示设备、部件、风险及关系，保留来源和权威等级。

为专门检查本轮构建，可在高级检索的 Document IDs 中填入权威来源和检修
报告的两个 Document ID，再执行一次；随后清空过滤器体验整个语料库的
自然检索。两次结果分开记录，限定文档的通过不替代无过滤的检索质量验证。

把图谱信任策略改成“仅权威实例”（`AUTHORITATIVE_ONLY`）再检索：模型新增的风险事实应
从**子图**消失，专家知识仍可见。该选项只约束子图投影，不会把原始检修
文档从文本召回中移除。当前 Playground 返回上下文及图谱，不生成最终回答。

## 9. 可选：同名设备、权限、回滚与撤回

**同名不同设备：** 上传 `homonym_report.txt`，使用其预填元数据和 LLM 模式。
设备仍名为“循环水泵”，但编码为 `BC-P-202`。如果模型正确抽取完整身份
属性，自动匹配应显示无匹配，不能链接成 `BC-P-101`。若编码漏抽，应显示
身份属性缺失等冲突，也不能自动合并。可以将该案例保留为候选，或按原文
审核并发布为新设备。

**权限：** 先记录两个 Document ID，再切到 Alpha · Public 或 Tenant Beta。
这些身份不应看到 Alpha Finance 的源文档、候选或图谱实例。检索台可能返回
它们有权限的其他基线文档；应检查本轮 Alpha 文档是否缺席。

**回滚：** 切回 Alpha · Finance + Legal，在 06 找到仅含专家实例的早期发布，
点击“回滚到此版本”。07 / 子图应回到对应知识状态；检修源文档仍保留，
因此文本检索仍可能召回它。随后可再次激活较新版本。

**撤回：** 建议用已经完成主流程的 `maintenance_report.txt` 体验。先恢复
包含检修知识的较新发布；确保本轮正确记录都已在 05 发布。04 只显示候选和
隔离记录，已批准但未发布的记录需要先在 05 完成发布，不能在 04 假定它们
已经被清除。剩余未采用的候选可在核对后拒绝。随后：

1. 在 07 用检修报告的 Document ID 筛选，勾选该文档的全部活动记录。
2. 点击“将勾选记录加入移除列表”，到 05 发布移除变更；保留权威来源的记录。
3. 在 09 点击“刷新活动文档”，确认检修报告没有阻塞，再点击
   “确认撤回此活动文档”并确认。

撤回保留历史审计和来源记录，但退出当前检索。如果仍有阻塞，按显示的
原因处理，不要直接删除来源数据。
当前发布规则不允许激活空知识集；上述操作保留七条专家记录。不要同时
移除全部专家与检修记录，否则会收到 409。

## 常见问题

- **403：** 检查治理身份和文档访问组。Public 身份不能做构建／审核。
- **409：** 刷新本体、候选或发布历史，检查是否重复导入旧记录、引用过期
  revision，或 active publication 已变化。不要清空既有数据来掩盖冲突。
- **504 / 503：** 查看构建任务。输入保持不变再提交，可以复用已完成的
  Chunk；不要不断变更文件、URI 或本体来制造新任务。SOURCE_ONLY 不调用
  抽取模型，但仍可能遇到 Embedding 或数据库依赖错误。
- **实例 JSON 未自动填入：** 确认下载的是原始权威来源文件、使用预填 URI、
  本体 key 和 SOURCE_ONLY 模式；若刚切换身份或刷新页面，可重复同源入库。
- **页面没有示例包或自动消歧：** 确认打开的是本轮 8002 入口并刷新页面。

可记录每一步的状态、任务／文档 ID、匹配理由及截图，特别是空抽取、模型
findings、同名设备处理和无过滤检索的实际结果。
