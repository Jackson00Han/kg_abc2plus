# 泵站维护知识构建：网页人工测试指南

这套材料将北辰泵站设备台账及配套实例约定为本项目的专家基准。
首次使用按页面 **01 → 02 → 03 → 04 → 05 → 06** 执行；以后添加业务文档，
重复 **04 → 05 → 06** 即可。

| 工作阶段 | 页面步骤 | 完成后得到什么 |
| --- | --- | --- |
| 建立专家基准 | 01 发布本体 → 02 上传权威来源 → 03 导入并发布专家实例 | 有来源依据、可用于匹配的权威知识 |
| 扩充业务知识 | 04 上传业务文档 → 05 确认实体并审核事实 → 06 发布业务知识 | 已审核、可用于图谱检索的新增知识 |
| 查看与维护 | 按名称打开清单、质量审计、发布历史或文档管理 | 检查或维护已有知识，不属于每次构建的顺序步骤 |

## 开始前：打开服务、选择身份、下载材料

服务入口：<http://127.0.0.1:8002/playground>。进入“知识构建”，在
“当前治理身份”选择 **Tenant Alpha · Finance + Legal**。
本次上传的文档访问组都只勾选 **alpha-finance**。

如果要从头重做整套测试，点击知识构建页顶部的 **“全部重新开始”**，核对
弹窗中的清理范围，再点击 **“确认清空并重新开始”**。这会清空本地演示环境
所有身份的本体、专家实例、上传文档、抽取、审核、发布及历史记录；自带的
10 份检索示例文档和 120 个片段会恢复，电脑里下载的文件不受影响。
成功后页面自动返回 01，并保留所选身份。只关闭弹窗或点击取消不会清空数据。
若仍有任务执行，等待其结束后再操作；重置期间刷新页面仍可看到状态。
重置失败时按弹窗重新确认后重试，其他旧标签页须刷新后继续。

展开“泵站维护示例包 · 下载材料与填写表单”，下载前两份文件。
也可以直接使用仓库中的文件：

| 文件 | 本次用途 |
| --- | --- |
| [authoritative_source.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/authoritative_source.txt) | 02 上传的权威来源：泵站、设备、机械密封及其属性和关系 |
| [maintenance_report.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/maintenance_report.txt) | 04 上传的业务文档：设备检修记录及新增渗漏风险 |
| [homonym_report.txt](../src/graphrag_prod/playground/static/industrial-demo-v1/homonym_report.txt) | 可选反例：同名、不同编码的另一台泵 |

文档、版本和 Chunk ID，生成对应的专家实例草稿。

## 1. 定义并发布本体（01）

1. 在示例包点击“载入示例本体到 01”。
2. 查看本体 JSON：key 为 `pump-maintenance-demo`，version 为 `1`。
3. 点击“导入为草稿”，再在该版本卡片点击“发布此版本”。

**完成条件：本体状态为 PUBLISHED。** 只有导入草稿还不够；下一步仅上传
权威来源，也要求此本体已发布。

这份本体规定：设备编码 `EquipmentCode` 用于辨认设备，额定功率
`RatedPower` 以 kW 表示。设备名称相同，不代表它们是同一台设备。
如果已有同 key 的已发布本体，检查后继续，不要反复导入旧版本。

## 2. 上传权威来源（02）

1. 在 02 点击“填写本步骤的示例信息”。
2. 在 02 选择 `authoritative_source.txt`，确认访问组为 `alpha-finance`。
   标题、来源 URI、来源名称、语言及本体 key 使用预填值。
3. 点击上传按钮，等待切块和向量化完成。

**完成条件：SOURCE_ONLY、1 Chunk，并提示专家实例已填入 03。**
权威来源这一步不调用 LLM 抽取；此时已有来源文档，专家实例仍是表单草稿。
接着向下进入 03。

也可以直接选择文件，使用页面生成的普通上传地址。系统按**文件内容校验和**
及示例本体识别配套实例，不要求来源 URI、标题或文件名与预填值相同；实例引用
本次上传返回的真实文档、版本和 Chunk ID。若内容或本体不匹配，03 会显示
具体原因，不能把“来源已入库”误认为“专家实例已准备好”。

如果这里还没有实例，先看输入框下的说明，再点击“前往 02 准备权威来源”。
使用示例时，上传未修改的 `authoritative_source.txt`，并使用已发布的
`pump-maintenance-demo` 本体；自有资料则需要按实际证据填写专家实例 JSON。
空表单不能导入。已经完成 01 的本体发布无需重做，也无需清空环境。

1. 查看已填好的实例 JSON，核对设备编码 `BC-P-101`、功率 `37.5 kW`
   及其原文证据。
2. 点击“校验并导入权威层”。
3. 导入成功后，在**同一区域**点击“发布专家基准”。

**完成条件：专家基准发布成功。** 本次专家基准有 7 条记录：

| 类型 | 内容 |
| --- | --- |
| 3 条实体提及 | 北辰水处理一号泵站、循环水泵、机械密封 |
| 2 条属性 | 设备编码 `BC-P-101`、额定功率 `37.5 kW` |
| 2 条关系 | 循环水泵安装于该泵站、循环水泵包含该机械密封 |

这些记录属于 **AUTHORITATIVE / EXPERT_IMPORT**。
点击“开始扩充业务知识 →”，继续 04。无需去下方业务发布区发布这批专家记录。

## 4. 上传业务文档（04）

1. 在 04 点击“填写本步骤的示例信息”，无需回到顶部示例包。
2. 选择 `maintenance_report.txt`，访问组仍为 `alpha-finance`。
3. 点击上传并抽取的按钮，等待完成。

**完成条件：文档已切块、向量化，并出现待审核的抽取结果。**
接着向下进入 05；队列载入后会自动计算实体匹配建议。

模型输出可能变化，不以固定的候选数量判断成功。若任务显示失败、拒绝或没有
候选，页面会说明“原文已入库，但未生成可审核记录”，不显示下一步审核按钮。
先查看下方构建明细；原文入库成功不代表已生成图谱知识。
不要为凑齐示例数量继续批准或反复上传。

## 5. 先确认实体身份，再审核属性与关系（05）

这个区域分成 **“1 确认实体身份”** 和 **“2 审核属性与关系”**。
页面会提示待处理事项及阻塞原因。先完成实体确认，再按照事实表的检查结果
操作；不要将所有记录一起批准。

### 5.1 确认文档里说的是哪个实体

查看实体卡片中的名称、原文和自动匹配依据，再按实际结果操作：

| 本例实体 | 核对内容 | 操作 |
| --- | --- | --- |
| 北辰一号循环水泵 | 编码为 `BC-P-101`，匹配到权威实体“循环水泵” | 点击“确认使用已有实体”，填写审核依据并确认 |
| BC-P-101机械密封 | 别名和来源支持匹配到权威实体“机械密封” | 点击“确认使用已有实体”，填写审核依据并确认 |
| 机械密封渗漏风险 | 原文确实提到该风险，且没有可链接的已有实体 | 点击“确认新实体” |

如果另有一条同名水泵提及，显示“缺少身份属性”或冲突，就对**那条提及**
选择“暂缓处理”。它会保留在暂缓区；不用反复点击，也不要把它当成新设备批准。

**完成条件：准备采用的实体已有明确身份；不确定的提及已暂缓。**
确认实体只处理身份，不会同时批准它的属性和关系。

### 5.2 审核这个实体的属性和关系

在水泵的事实表中，逐行看“内容、原文证据、检查结果”。
本例通常有以下四项：

| 抽取内容 | 与已发布专家基准比较 | 操作 |
| --- | --- | --- |
| 设备编码为 `BC-P-101` | 已有相同编码 | 点击“保留已有事实，不重复入图” |
| 额定功率为 `37.5 kW` | 已有相同功率及单位 | 点击“保留已有事实，不重复入图” |
| 包含 `BC-P-101机械密封` | 设备和部件链接后，与已有包含关系一致 | 若页面判定重复，点击“保留已有事实，不重复入图” |
| 存在“机械密封渗漏风险” | 新关系，原文支持 | 设备和风险实体确认后，点击“批准此事实” |

“保留已有事实，不重复入图”会记录本次处理原因，保留原文和抽取审计，
继续使用已发布事实；它不会把正确的重复内容当作新的图谱事实发布。

遇到其他检查结果，按下面处理：

- **关联实体尚未确认：** 按该行的提示先完成对应实体确认；此时不能批准关系。
- **冲突：** 查看并排展示的新旧值、单位、适用时间和来源；暂不能判断就暂缓。
  不把不同值当成重复，也不覆盖已有权威事实。
- **原文不支持：** 点击“不采纳”。

**完成条件：本次准备采用的事实已经审核，重复项已经明确保留已有事实，
不确定项已经暂缓。** 不要求队列中所有记录都变成“批准”。

只有本次确有已批准内容，且当前批次没有待处理实体或事实时，才显示下一步
发布按钮。空队列表示“当前没有待审核记录”，不代表审核或知识构建已经完成。

正常审核无需修改 JSON。需要修正抽取内容时，再打开技术详情并使用“编辑内容”；
修改后只能点击“保存修改并暂缓复核”，生成新的记录版本，再等待身份匹配或
事实检查完成。核对新版本正确后，再明确批准；旧版本的检查结果不能用于批准
修改后的内容。编辑期间，普通审核、实体链接及保留重复事实的操作暂停；
“取消编辑”会恢复原内容和对应操作。

## 6. 发布业务知识（06）

1. 查看审核通过、尚未发布的业务记录。刷新页面后可点击“刷新可发布候选”恢复列表。
2. 核对本轮要发布的记录，点击“发布变更集”。
3. 确认发布成功。

**完成条件：审核通过的本轮业务知识进入当前生效版本。**
已判为重复或暂缓的记录不应加入这次发布。专家知识保留权威来源；
模型提取并经人工审核的知识仍是 **SECONDARY / LLM_EXTRACTED**。
“审核通过”和“已发布”是两个独立状态。

至此主流程完成。以后添加业务文档，从 04 开始即可。

## 可选测试与问题排查

以下内容用于进一步验证，不需要穿插在首次主流程中。

### 同名设备与缺失身份依据

在 04 上传 `homonym_report.txt`。其中“循环水泵”的编码是 `BC-P-202`，
不能链接到 `BC-P-101`。有完整身份依据但无匹配时，可核对后确认新实体；
漏抽编码或存在冲突时应暂缓。

`homonym_report` 曾因模型将属性证据截得过短、纠错时又把整句标成实体提及，
两轮出现 `ENDPOINT_OUTSIDE_EVIDENCE`。新版抽取已增加实体边界说明和具体坐标
纠错反馈，并保留严格校验。升级后刷新网页，在 04 用原文件重新发起一次构建；
旧任务仍显示原来的失败记录，不会自动变成成功。若新的任务仍失败，保留该次
构建明细用于排查，不要反复提交。验证记录见
[同名设备抽取纠错](validation/homonym-extraction-correction.md)。

页面按实体 ID 组织记录，不会按同名直接合并。每条提及仍有独立证据和审核状态；
当前匹配只读取绑定到该条提及版本的身份属性，不会自动借用另一条提及的编码。
复杂文档中的跨提及身份传播仍是独立待办。

另一个纠错限制发生在**同一条提及的新旧版本之间**：对实体执行普通暂缓或
保存修改并暂缓，会生成新 revision，但不会迁移其依赖事实。若设备仍使用模型
临时身份，编码事实可能仍绑定旧 revision，新版本因此显示身份属性缺失。
此时保留暂缓，不要反复批准或改编码绕过检查。正常匹配应使用“确认使用已有
实体”，该操作会原子重绑依赖事实；普通暂缓和实体纠错不具备这一迁移能力。

当前重复检查比较的是同一本体下、当前生效且有权访问的权威事实；模型候选
之间的重复不在本次自动识别范围。值或适用时间不同表示需要人工核对，不等于
原文错误，也不代表系统已经判定多值属性或历史更新是否应当共存。

### 权限与图谱信任策略

- 切换到 Alpha · Public 或 Tenant Beta，本轮 Alpha Finance 文档、候选和
  图谱实例应不可见。其他有权限的基线文档仍可能出现在检索结果中。
- 在检索台将图谱信任策略设为“仅权威实例”，新增风险应从子图消失。
  此选项只约束图谱投影，原始检修文档仍可能被文本检索召回。
- 切换身份会清除当前实例草稿及匹配结果，建议完成主流程后再做权限测试。

### 回滚与撤回

在“查看与维护”的“发布历史与回滚”选择较早版本，可以检查图谱恢复到
对应发布状态；原始文档仍在，因此文本检索仍可能召回它。随后可恢复较新版本。

要撤回本轮检修文档，先在“活动 A-Box 清单”按该文档 ID 筛选，将其活动记录
加入移除列表，再在 06 发布移除变更。然后到“活动文档与受治理撤回”，刷新并
按提示处理阻塞，最后明确确认撤回。保留专家基准，不要发布空知识集。
撤回退出当前检索，保留历史来源、审核及发布审计。

### 上传、匹配和发布遇到错误

| 现象 | 先检查什么 |
| --- | --- |
| 403 | 治理身份及文档访问组；Public 身份没有构建、审核权限 |
| 上传提示版本冲突 | 01 的本体是否已经 PUBLISHED；草稿不能用于本次构建 |
| 审核或发布提示版本冲突 | 刷新对应候选或发布状态，检查是否已有新 revision 或当前发布已变化 |
| 实例 JSON 没有自动填入 03 | 原文内容是否与配套文件完全一致、本体 key 是否正确；是否刚刷新网页或切换身份（URI、标题、文件名无需与预填值相同） |
| 刷新后找不到 03 的专家发布按钮 | 恢复同一份实例 JSON，重新“校验并导入权威层”，再在本区域发布；已生效的相同记录不会重复发布 |
| 匹配显示依赖错误 | 保留候选；依赖恢复后点击该项“重新匹配” |
| 构建失败、拒绝、503 或 504 | 查看任务明细，记录实际错误，不连续点击上传 |

权威来源表单预填丢失时，可用同一文件、URI、访问组再次执行仅入库，幂等操作
不会多建一份来源文档。修改过文件内容时，不会继续套用旧实例的证据坐标。

抽取模式对每个 Chunk 最多进行一次校验纠正；模型服务错误或超时不触发自动
纠正。任务明细保留逐轮校验摘要。当前开发配置中，LLM 模式最多 2 Chunks，
仅入库最多 4 Chunks；每次模型调用限 30 秒，整个构建限 90 秒。仅入库不调用
抽取模型，但仍依赖 Embedding 服务和数据库。

遇到连接失败时，先点击“刷新构建任务”查看状态；刷新只查询，不会重新执行：

| 任务状态 | 接下来怎么做 |
| --- | --- |
| 处理中（RUNNING） | 等待，再刷新查看；不要重复上传。 |
| 已失败（FAILED） | 查看卡片上的原因。向量化连接失败表示尚未进入本次 LLM 抽取；连接恢复后，用相同文件和表单再次点击上传，创建新任务。旧失败记录保留。 |
| 已中断，等待重试（RETRY_WAIT） | 依赖恢复后保持输入不变重试，仍使用原操作，可以复用已完成的 Chunk。 |
| 已完成（COMPLETED） | 查看任务明细，按结果进入下一步。 |

如果请求报错但尚不能确认结果，页面会保留原操作编号，避免重复入库。
只有确认任务已结束才使用新编号；不要通过连续提交掩盖连接问题。

### 专家实例的发布范围与批量限制

03 只发布最近一次成功导入返回的记录，不会带上其他待发布知识。重新导入会
清除上一批的本地发布选择；若导入失败，先修正本次错误再导入。刷新页面后，
可重新导入同一批实例恢复发布选择；这些记录若已生效，只确认完成，不重复发布。

全新记录按导入返回的完整记录列表提交，由后端逐项校验。更新已有专家记录时，
页面还需核对替换关系；本次尚未生效的记录必须全部包含在最多 100 条可见候选中。
不足以完整核对时，页面会明确阻止提交，提示先处理其他待发布记录或缩小更新
批次，避免遗漏替换。本指南的首次 7 条专家记录不受这项更新限制影响。

### 本地服务启动

如果服务已停止，在项目根目录运行：

```sh
PLAYGROUND_BOLT_PORT=17694 ./scripts/run_playground.sh --port 8002 --no-open
```

启动会建立临时数据库并加载 120 个基线 Chunks。关闭启动进程会清理该临时
数据库；本指南材料保存在仓库中，可以重新执行。使用 8002 正式测试入口，
不需要临时 8003 入口。
