# 本体文件上传与规范化

入口：`http://127.0.0.1:8002/industrial` → 登录并选择知识库 → **知识构建** → **本体构建**。
构建入口需要当前身份具备管理权限；服务端继续按认证身份执行本体权限与租户隔离。

本体编辑区默认空白，不自动加载平台默认 JSON、示例本体或当前活动本体。
已经保存的本体版本继续保留在下方列表，已有知识与发布历史保持原本体版本绑定。

## 操作流程

1. 点击 **选择本体文件**，选择 `ontology.yaml`，也可选择 `.yml` 或兼容的 `.json` 文件。
   浏览器读取 UTF-8 原文后自动请求后台诊断，不在浏览器解析 YAML。
2. 查看校验结果中的本体标识、源版本、系统版本、实体类型数、关系类型数和属性定义数。
   错误显示诊断原因，以及可定位的字段路径、行号和列号；展开 **查看规范 JSON** 核对转换结果。
3. 需要修改时展开 **查看或编辑本体源文件**，修改后点击 **后台诊断与校验**。
   内容或规则引用目录一经变更，原校验结果失效，须重新校验才能保存。
4. 校验通过后点击 **保存本体版本**，保存为 `DRAFT` 草稿。保存时后台再次解析和校验，
   并核对先前诊断的原文哈希与规范本体校验和。保存草稿不会启用新本体。
5. 在 **已存本体版本** 中核对版本，再显式点击 **启用此版本**。
   启用成功后可在实例构建中选择此本体；已有知识的发布流程与本体版本约束继续生效。

列表支持 **载入并校验**、**复制为下一版本**、**导出 JSON**。
复制下一版本是显式操作，不是登录后的默认填充。切换身份或知识库会清空上传内容、
校验结果和待保存状态；旧请求的响应不能覆盖新身份下的页面。

## 接受的本体定义

注意区分同名文件：项目 `new_files/ontology.yaml` 是八节结构的 4.0.0 原始定义，
目前没有直接编译适配器。该原始包整理后的可上传定义为
[`busway_files/ontology.source.json`](../busway_files/ontology.source.json)，源版本为 5.0.0。
V11 包使用另一份七节属性图定义；应按资料所属知识包选择本体，不能只凭文件名混用。
模型服务连通不代表所有本体格式都已接入，本体结构校验本身不调用模型。

文件扩展名只决定输入容器；定义仍须符合已支持的本体契约。任意 YAML 配置文件、
设备拓扑或知识文档不能作为本体直接保存。

| 定义形态 | 处理方式 |
| --- | --- |
| v11 所用七节属性图定义，`metadata.model_kind: property_graph` | 使用 `property_graph_authoring_v1` 配置编译；类型名、属性和约束来自上传文件 |
| 既有 `ai_power.knowledge_ontology@1.0.0` 十节源契约 | 沿用已有源契约编译与实例化边界 |
| 平台原生 `key`、整数 `version`、`entity_types` 等 JSON 定义 | 沿用平台 T-Box 结构与约束校验 |
| 平台导出的 `graphrag-property-tbox-export-v1` JSON | 校验导出包装及预期校验和后读取其中的定义 |

七节属性图定义包含 `metadata`、`scope`、`layers`、`property_definitions`、
`entity_types`、`relation_types`、`constraints`。编译器检查声明结构、字段类型、
枚举及格式、关系允许类型对、声明引用、身份定义，以及受支持的联合属性和工程结构约束。
不支持或自相矛盾的声明返回错误，不静默丢弃后继续保存。

规范 JSON 展开可执行的类型、属性、关系等定义，同时保留完整的来源定义。
源本体里的身份编号映射到平台稳定实体 ID 的约定，不授权按同名或工程短编号自动合并实例。
`layers` 中的等级与 `metadata.status` 保留为来源声明，不覆盖平台来源等级、审核状态或发布状态。

本轮诊断采用确定性的解析、结构与声明约束检查。它不调用模型进行语义改写，
也不证明领域定义在现实业务中已经正确、完整或经过专家认可。后续实例仍需接受
身份、证据、审核、发布及相应约束检查。

## 版本与可追溯原文

源版本 `major.minor.patch` 保留在来源定义中；系统版本沿用既有整数编码
`major × 1,000,000 + minor × 1,000 + patch`，例如 `0.1.1` 对应 `1001`。
页面同时展示两种版本，不能将系统整数当作来源文件的版本字符串。
已发布或停用版本不可直接改写；修改定义应复制并保存新版本，已有草稿更新保留预期校验和检查。

| 标识 | 作用 |
| --- | --- |
| `source_sha256` | 上传原文 UTF-8 字节的 SHA-256，包含注释、空白、换行与原有 BOM |
| `normalization_checksum` | 规范 T-Box 语义哈希，绑定定义及受支持的来源/规则目录内容，不包含租户或生命周期状态 |
| 来源契约的 `source_checksum` | 规范化来源 JSON 的哈希；它与原文件字节哈希分别记录 |

校验和用于内容一致性检查，不能作为权限凭据；相同定义在不同租户中可以具有相同校验和。
稳定 `tbox_id` 与原文记录 ID 包含租户绑定，服务端仍从认证身份确定保存位置。

保存时本体版本与不可变原文记录在同一存储事务中写入。原文记录保留文件名、格式、正文、
字节数、原文哈希、规范本体校验和、规范化版本和服务端认证的创建人。
每条转换记录还由服务端保存当次完整的规范 JSON 快照，包含独立选入的规则引用目录，
使旧草稿转换在后续修订后仍可重建；客户端不能提交或替换该快照字段。
草稿修订追加原文记录，不覆盖先前上传的原文；来源对象按租户和本体版本关联。
同一原文与同一规范结果重放复用一致的记录，不能以重命名覆盖其首次登记的创建信息。
同一原文搭配不同规则引用目录形成新的规范结果时，追加独立的转换审计记录，保留旧记录。

当前 **导出 JSON** 提供本体定义及校验和，不是原始 YAML 文件下载。
新建的不可变原文记录用于保留上传依据；本轮未增加原始 YAML 下载页面。

## 文件与解析边界

- 本体文件必须为 UTF-8，非空且不超过 **1,000,000 字节（1 MB）**；规范化后的来源定义也受容量限制。
- 一次只接受一个文档。拒绝重复键、YAML 锚点及别名、合并键 `<<`、显式 YAML 标签，
  不加载外部对象，也不执行 YAML 中的代码。
- 顶层必须为对象，字段名必须为字符串；值须能表示为受支持的 JSON 值。
  解析还有 32 层嵌套、30,000 个节点和单字段 65,536 字符等预算。
- 可选的 **规则引用目录** 沿用既有 JSON 引用契约。选入或修改目录后重新校验；
  目录登记版本与条款引用，不在本轮执行规则或导入规则文件正文。
- 校验失败不保存本体，保存失败不启用本体。诊断只返回当前发现的问题，修正后应再次校验。

## API 与本轮范围

```text
POST /v1/ontologies:validate
POST /v1/ontologies:import-file
POST /v1/ontologies/{tbox_id}:publish
```

诊断接口接收 `filename`、`content` 和可选 `rule_reference_registry`，返回
`ontology-source-validation.v1`：校验状态、诊断、摘要、规范定义、原文哈希及规范本体校验和。
此操作只读，不写入本体。

原文件保存接口重发相同内容，附 `expected_source_sha256`、
`expected_normalization_checksum`；草稿更新可附 `expected_checksum`。
页面显式提交 `activate: false`。保存与诊断都需要 `ontology:write`；
启用还需要既有 `ontology:publish` 权限。租户与创建身份由服务端会话决定。

本轮只建设本体输入、校验、规范化和版本保存链路。上传本体不自动读取 topology 或知识文档，
不导入实例，不发布图谱知识，不执行诊断规则，也不改变现有资料、证据、审核和知识发布机制。

## 自动抽取兼容性

本体可以独立保存和启用。当前通用 LLM 抽取使用 `llm-candidate` 临时身份命名空间，所有允许实例化的实体类型须显式允许该命名空间；已有稳定身份约束仍保留。上传资料选择 LLM 抽取时，预检会检查此要求，不满足时返回 `422 construction_ontology_incompatible`，而非启动任务后返回依赖不可用。仅保存来源不受此要求限制。系统不会静默修改用户本体或放宽稳定身份规则。
