# Markdown 声明式映射执行

`construction/markdown_executor.py` 将经过版本管理的 `markdown-section-mapping:v1` 配置应用到原始 Markdown 表格，生成经过本体和精确证据校验的候选。解析、列映射和引用连接均由程序执行，不调用大模型。它不修改原文、补造外部定义、审批候选或决定发布。

映射预检仍由 `markdown_mapping.preview_markdown_mapping` 完成；原有 `PREVIEW_ONLY` 报告不会仅因预检成功变成已审核知识。执行器要求全部章节和列已有明确处置、本地定义满足本体属性和组合约束。只有端点定义已在同一来源中明确存在的关系才能执行。外部引用继续保留在审计和待补清单中。

## 候选与证据

- 实体属性的证据是包含名称和属性值的原始表格行；关系证据是同时包含来源引用、关系类型、目标引用及关系属性的原始表格行。候选仍经过现有严格校验器检查类型、方向、字面量、枚举、基数及精确位置。
- 名称取定义表的 `display_name` 单元格。关系表中的章节引用必须解析到已校验的定义；不是按相同显示名称合并。稳定候选身份绑定租户、文档、本体、映射标识和映射中的来源身份。同一来源的定义行及各关系行复用该身份；不同来源仍须另行做受治理身份关联。
- 完整定义章节、模拟声明和其他上下文章节保留在来源预检审计中，锚定同一不可变文档版本。执行摘要和每片审计携带语义上下文。模拟知识仍是概念与候选解释，不变为设备事件、实测数据或工业验证结论。
- 不完整表格行跨越当前证据片段时明确拒绝，不能伪造提及、移动偏移或缩短证据。当前执行契约要求实体有来源明确的 `display_name` 单元格；其他形式的身份提及需要显式扩展映射。

执行器接口为 `MarkdownMappingExtractor(base, parsed, mapping)`，具有 `prepare_document`、`extract_audited`、`summary` 和 `semantic_context`。声明 `deterministic_batches=True`、`max_document_model_calls=0`；准备阶段仅保存有范围和校验和的映射执行记录。来源完整保存、嵌入、候选持久化、审核及发布继续由工作流完成，执行器不会绕过这些步骤。

映射记录的形成方式为 `MAPPED`，不会冒充模型生成。准备阶段的不可变制品保存完整 `mapping_profile` 与执行摘要。`knowledge/markdown_review_evidence.py` 可在获得授权的审查中重放原文和映射，将所有预期提及、断言、类型、身份、证据、字面量、端点、来源等级及当前修订与待审记录逐项比较，输出带校验和的审查清单。它不执行批准或发布；身份确定及审批仍经过现有审核服务的权限、版本及事务检查。

## 工作台上传入口

在「知识构建 → 实例构建」选择原始资料后，展开「来源信息与处理设置」，通过「声明式映射（可选）→ 选择映射 JSON」显式载入配置。当前 V11 的 XML 配置为 `busway_files/v11-reference/topology-mapping.json`，模拟知识 Markdown 配置为 `busway_files/v11-reference/knowledge-mapping.json`。文件名不参与映射选择或事实推定。

页面显示映射标识与版本，可清除后恢复普通切片设置。XML 映射使用最多 65,536 字符的完整结构证据；Markdown 映射使用 3,000 字符、结构优先的片段。上传前先执行同一后台预检；「预览切片」同时显示映射对象、关系声明、未解析引用和诊断。预检不会保存来源、构建候选或调用提取模型。「仅保留来源」仍保留映射预检，但不生成候选。

本体或知识库身份变化会清除当前映射；异步文件读取不能恢复已清除或其他身份的配置。映射 JSON 限制为 256 KiB、UTF-8，拒绝重复字段、未知版本、过深结构及非有限数值。完整配置进入构建请求和操作指纹，服务端仍独立校验。自动生成的来源 URI 保留文件名的 Unicode 编码，避免不同中文文件名均退化为 `.md`；来源 URI 仍可在页面显式编辑。
