# 上传状态与来源版本冲突修复（2026-09-11）

## 原因及实际状态

在当前 8002、`pump-only` 工作区只读核对了用户反馈的构建任务、发布历史和候选元数据：

- 已发布构建任务 `9027230e-f043-57ac-bd7a-ae3f57f0875d` 使用文档 `4751bc38-2710-5262-90e6-bc64d63ef84a`、版本 `e374bebf-1983-5349-bf58-bf0bc2d36d39`。
- 随后的任务 `81458fe3-75ee-5a19-9b46-65ddd77f2504` 使用相同文档、版本 `4b838e36-21de-52b6-86bc-2c7a9dec1bbd`；当前有 7 条可发布候选。
- 活动发布仍绑定第一份任务的快照。真实发布预览返回 409 / `SOURCE_VERSION_CONFLICT`，保护同一发布的来源版本一致性。

前端切换资料类型原先只更新说明，文件、标题、来源 URI 和构建回执仍保留；选择另一文件也只填充空的标题和 URI。因此独立业务资料可能被作为上一份权威资料的新版本写入。预览失败时又未清除上次成功发布的 JSON，让历史回执看似本次结果。这不是要求用户清空知识库才能解决的问题。

## 修改范围

- 切换资料类型清除当前文件、标题、URI、设备编码、构建结果和下一步提示；保留本体、处理方式、访问组、审核记录及发布选择。普通步骤或页签导航保持草稿。
- 选择新文件时更新自动生成的标题和 URI；已完成构建的草稿不再向下一文件沿用旧来源。尚未提交时用户明确填写的元数据仍可用于有意更新原文。
- 构建时固定上传字段，按钮显示动态进度，旁边提供状态说明；不再显示右下角浮动进度或占用结果区。结束或失败后恢复控件，切换步骤不覆盖正在进行的说明。
- 切换资料或选择文件后，较早发出的任务详情请求不能恢复旧结果。
- 发布选择失效或重新预览时隐藏旧发布回执；成功发布的回执在刷新相关列表后展示。版本冲突补充来源 URI 说明、独立资料与原文更新的处理路径，以及返回上传入口。
- 没有修改来源版本约束、后端查询、事务或持久化，也没有清理或重绑现有候选证据。
