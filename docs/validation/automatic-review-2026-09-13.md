# 构建后的自动预审（2026-09-13）

## 目标和接入

用户授权在重置后的母线槽知识库实际导入本体与权威拓扑，验证“自动确认确定项、人工处理未决项”。本次不自动发布实例知识、不重置数据库、不恢复隔离语料。

8002 的 LLM 构建完成后，`Neo4jKnowledgeOperations.construct()` 调用 `Neo4jAutoReviewService.run()`。上传及预审共享构建请求预算；预审失败不掩盖已成功持久化的上传，回执明确显示失败，允许单独重试。SOURCE_ONLY 不触发预审。运行入口在 `scripts/run_playground.py` 注入同一个配置模型的独立审核器，其他服务部署需显式配置该服务。

新增受认证 API：

- `GET /v1/knowledge/construction-jobs/{job_id}/auto-review`：读取受权限保护的摘要。
- `POST /v1/knowledge/construction-jobs/{job_id}/auto-review:run`：`{"retry":true}` 明确重试；不自动重试写请求。
- 构建响应及单个任务详情增加可选 `auto_review`；任务列表保持原有有界查询，不为每行另查详情。

当前两个预审接口均要求审核与构建权限，沿用现有构建任务的访问契约。调用者身份由服务端认证恢复；自动审核使用独立服务身份并保持调用者的租户、组和能力范围，记录发起者，不提升来源等级。

## 执行原则

1. 重新读取不可变原文、本体、映射摘要与当前候选版本，校验全部来源记录范围和引用。
2. 同来源稳定 ID 的提及归组；跨来源只接受本体声明且有证据支持的身份信息。名称相同不能自动合并，多个来源 ID 不能凭传递相似性归为一个实体。
3. 模型一次审核多个对象组，返回引用原文和候选目标的结构化建议；服务端进一步检查完整性、类型、身份冲突与版本。
4. 经现有审核事务确认身份；涉及绑定时同步重绑关联事实，事实仍需单独审核。
5. 按本体类型、字段及关系映射组织事实审核，程序逐条验证原文、值、端点和冲突，模型审核映射语义与样本；不把抽样模型审核表述为模型逐条阅读全部事实。
6. 疑难、被人工暂缓、缺少来源证明和依赖未决项留在人工流程。模型或服务故障属于未完成，不冒充人工判断完成。
7. 自动批准进入 `APPROVED`，发布仍是独立操作。保留原文、模型审计、策略、执行人、版本及每次写入结果。

模型输出不是脚本；不执行模型生成的代码或查询，不接受模型自报置信度作为批准依据。每个模型批次限制输入和输出，最多一次结构纠错，关闭 SDK 隐式重试。模型原始请求和响应保存在受保护审计中，不放入 HTTP 摘要或普通日志。

当前每批 8 个对象/映射组，最多并发 3 个模型请求，写入仍串行经过审核事务；超过输入边界进一步拆批。单次模型 60 秒，每次预审最多 40 次调用，一个任务累计最多 80 次，每次预审最多 1,200 秒。状态与审计保留实际调用次数；重试只处理尚未确认的记录，不重新上传或覆盖人工决定。

模型只为顶层 `records[].record_id` 返回决定；嵌套的 `samples[].sample_record_id` 是映射语义的证据样本。程序检查该组所有事实的源字段、原始值、引用和冲突。返回多余或遗漏的决定时整批拒绝，给出完整允许 ID 清单纠错一次，仍不合规则明确未完成。

## 界面

上传后显示身份审核、事实审核阶段。回执分别统计自动通过的对象组/提及/事实、人工判断、依赖阻塞和未完成。人工队列继续只读取候选和暂缓记录；自动通过记录可查看审核依据、原文并转回人工处理。模型输出必须经过白名单和 HTML 转义，身份或知识库变化后的旧请求不得更新新页面。

预审摘要有展示上限并优先展示未决项目；展示截断不改变后台审核范围。具体规模限制与不完整状态由 API 返回，不能把截断或未完成当作全量成功。

增加只读 `issues`：已确认实体缺少本体必填属性事实时按属性汇总，包含影响实体数、代表提及和同名上下文路径。一个问题最多返回 200 个实体/记录 ID，最多返回 100 个问题；截断显式标记。即使人工记录队列为空，仍提示映射缺口。上下文路径只是核对提示，不自动继承为实体属性。

## 当前支持范围与限制

- 自动放行目前依赖经验证的结构化 JSON 字段映射与稳定来源身份；实现不判断文件名或母线槽类型。普通文档或未建立此来源证明的记录继续走人工流程，不能据此声称所有格式均可自动确认。
- 跨来源自动绑定需要本体声明的完整身份属性及当前有效证据。仅同名、身份字段缺失或多个既有目标冲突都不会自动合并。
- 当时拓扑有 24 个资产缺少 `project_id` 属性事实：值在 `/metadata/project_id`，而 `/metadata/source_location/project_id` 是来源位置说明，不能作为属性值。审核完成后集中提示 1 项映射缺口；没有降低本体必填约束或修改原始文件。
- 此阶段尚未实现全局上下文映射与跨 Chunk 双证据。后续修复及其独立验收见 [JSON 上下文属性映射与增量补全](context-property-mapping-2026-09-14.md)；本报告以下计数保留为修复前基线。
- 必填字段检查面向当前有效来源和本体，不能替代发布预览的全部约束。来源撤回、本体切换或比较范围超过上限时明确不可用；不把历史审核回执当作当前发布许可。

真实浏览器操作使用现有 8002 母线槽知识库（用户重置后的 generation 5），保持 `pump-only`。上传本体 `ai_power.busway.ontology v5.0.0` 和规则引用目录成功并启用本体；上传原始 `busway_files/topology.source.json` 成功持久化，任务 `a85f4970-47a0-5105-95e7-b2425b5a5fc8`。未创建替代语料、未重置库、未发布实例。

20 个片段全部处理完成，其中 18 个产生抽取结果、2 个仅包含没有映射为事实的上下文。139 个来源对象形成 310 条提及、898 条属性及关系。真实模型最终自动确认全部 139 个实体组、310 条提及和 898 条事实；未决判断、依赖阻塞和未完成请求均为 0。必填 `project_id` 映射缺口仍为 1 项、影响 24 个实体。

实测发现并修复：

1. 初版 24 组/批及长输出触发 60 秒超时；调整为 8 组/批、简短理由、有界并发。真实 8 组身份探针两次分别约 25.7/26.5 秒。
2. 持久化回执的 ISO 时间字符串被严格 HTTP DTO 拒绝，导致已持久化的构建返回 503；现按既有 API 时间解析契约校验，API 回归覆盖此路径。
3. 某 4 组事实的 12 个样本被模型逐一返回，违反顶层 4 项协议；未直接过滤放行。明确审核单位并改名样本 ID 后，真实探针 13.347 秒、一次调用返回准确 4 项建议，覆盖原先未完成的 30 条事实；实际重试成功。
4. 浏览器最初错误地检查隐藏进度元素的残留文字，误报未结束；截图实际已显示终态。进一步用延迟队列/晚到轮询测试复现了旧进度覆盖终态的竞态，现上传及重试接受终态后立即停止轮询。回归从失败转为通过。
5. 实际原文截图暴露 HTTP 响应的全局字符串去空白设置改变了缩进，导致高亮位置偏移。`ReviewEvidenceResponse.text/quoted_text` 现使用精确保留空白的证据类型；API 测试及真实浏览器均校验上下文长度和命中子串与原文引用一致。

最终模型调用累计 37 次，包含早期失败及纠错，不是干净运行耗时基准。调整后主体重试从 15:46:06 到 15:52:09 UTC 约 6 分钟，完成全部身份与 868 条事实；剩余 30 条修正后单独重试完成。不能据此承诺任意文件秒级完成，仍需在稳定配置下另做规模基准。
