# 有界来源摘录

完整导入单元和回答上下文分别受限。确定性 XML 映射可以保留一整个不可变来源 Chunk；检索不得因为它大于上下文预算而直接丢失该来源，也不得把全文无限传入模型。

## 精确来源窗口

`retrieval/excerpts.py` 定义 `exact-source-window:v1`：先按现有权限、发布版本、向量/BM25 与 RRF 排序得到候选，再在授权原文中裁剪。没有新增相关性评分。

- 普通 Chunk 不超过请求 `max_context_chars` 时保留全文。
- 超长 Chunk 返回不超过 `min(6000, max_context_chars)` 个 Unicode 字符的连续原文。按问题中的精确字面词首次命中位置选窗，无命中则返回明确标记的开头摘录。它不是文档摘要，也不保证涵盖问题的所有证据。
- 每个窗口先验证完整 Chunk 的 SHA-256 和字符范围；排序后的上下文仍通过原有 `select_context` 总字符/片段预算检查。已标为摘录的窗口可缩至实际剩余字符预算，避免前序普通片段占用后再次整块拒绝；选择仍按原有核心片段、相邻片段、排名补足顺序，普通全文片段不自动截断。实际分配记录为 `remaining-budget:v1` 策略，绑定检索 trace 身份。
- `trace.decisions` 增加 `truncated / exact_source_excerpt`；前端和回答提示明确标记不完整，不能从摘录推断全文不存在其他内容、完整数量或完整拓扑。
- 完整来源仍通过原有受授权来源接口读取；不覆盖原 Chunk、不改变稳定 ID 或原始校验和。

## 引用兼容

普通引用保留现有含义，新增字段默认为 `is_excerpt=false`，其余为空。摘录引用包含：

| 字段 | 含义 |
| --- | --- |
| `char_start` / `char_end` | 本次返回文本在原文中的绝对字符范围，左闭右开 |
| `source_char_start` / `source_char_end` | 原不可变 Chunk 的完整绝对字符范围 |
| `chunk_checksum` | 完整不可变 Chunk 的 SHA-256，保持原含义 |
| `excerpt_checksum` | 返回摘录 UTF-8 字节的 SHA-256 |
| `is_excerpt` | 明确为 `true` |

字符偏移采用服务端 Unicode 字符索引，不是 UTF-8 字节或 JavaScript UTF-16 索引。客户端核对文本时应采用等价的 Unicode 码点切片。API 分别验证完整文本或摘录的长度与对应校验和；两种校验和不混用。回答引用沿用同一结构，生成提示版本为 `1.5.0`。

回答执行前后仍使用当前租户、文档与 Chunk ACL、发布/本体/来源版本重新授权，重读完整来源后严格复现摘录，再比较返回文本及所有引用元数据。撤权、原文变更、伪造范围或摘录校验和不匹配均拒绝。

## 可选重排

现有重排提供方单项输入上限为 3600 UTF-8 字节。重排候选可以使用独立的最多 2400 字节连续精确窗口，为源标题、章节和明确摘录标记预留空间；提供方对最终渲染输入再次执行完整上限检查，过长元数据仍拒绝，不静默截断或回退。

重排候选保留完整 Chunk 校验和，附加窗口范围及摘录校验和。实际渲染版本追加 `+exact-source-window:v1`，缓存身份绑定这些字段和实际渲染正文校验和。普通完整候选的渲染与缓存身份保持兼容。重排后重新读取并授权完整来源及候选窗口，最终回答上下文按上述请求预算独立选择。重排分数不解释为事实置信度。
