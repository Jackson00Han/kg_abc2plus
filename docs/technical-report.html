01 / 10

项目定位：GraphRAG 不是“图数据库 + LLM”

这个项目解决的不是一次问答演示，而是如何让每个事实都可回到原文、每次检索都不越权、每次发布都不暴露半成品，并用机器报告证明这些条件持续成立。

What it is

证据优先的参考实现

  • 多租户、组级 ACL 的文档摄取与查询。
  • 文档版本、Chunk 坐标、校验和与派生事实全链路 provenance。
  • Vector / BM25 双路召回，标准 RRF 融合，RA 图扩展。
  • 服务端校验 Claim、Quote、数字与 Citation 的 grounded generation。
  • Gold、基线、故障、恢复、性能与成本统一回归门禁。
What it is not

不是无条件上线的托管产品

  • 没有生产 Dockerfile、Helm/Kubernetes 或完整部署拓扑。
  • Stage 9 默认使用确定性本地 embedding 与 recorded-answer provider。
  • 没有替客户完成数据治理、外部身份、TLS、合规与 on-call。
  • 五分钟单容器参考负载不等于集群容量或长期稳定性证明。
  • 生产包是可装配的库与验证边界，不是已经配置好的 SaaS。

两条并行路径。 src/01…06 保留为教学路径，展示从基础向量检索到图增强问答；真正的工程实现位于 src/graphrag_prod，后者以领域边界、事务语义、安全和验证为设计中心。

03 / 10

数据与图模型：来源层、派生层、发布层分离

所有持久业务 ID 都是确定性 UUIDv5；Chunk 用标准化原文中的绝对半开区间和 SHA-256 定位。Neo4j 的内部 elementId 不承担业务身份。

Entity A← SUBJECT —Assertion— OBJECT →Entity B / literal· EVIDENCED_BY →Chunk
Identity稳定且可重建

Document、Version、Chunk、Entity、Mention、Assertion、Embedding 都由明确输入生成稳定 ID。

Provenance事实有原文坐标

派生关系保留 extractor 版本、置信度、evidence Chunk 与精确范围，可反向审计。

Publication快照原子可见

构建中的图不可见；manifest 校验通过后再切换活动快照和文档版本。

关键语义：Entity 和 Assertion 是派生导航数据，不自动成为回答事实。即使图上存在一条关系，生成器仍必须拿到授权的源 Chunk，并用其中的原文支持 Claim。

增量摄取与原子发布

Provider 工作在短事务之外，结果以稳定 artifact ID 缓存；只有经过治理并封存的 Snapshot 才能成为活动读模型。

  2. 持久化作业Job / Task、attempt、lease 与随机 fencing token。
  3. 派生 Artifact拆分、抽取、embedding；命中缓存或幂等计算。
  4. 图治理类型、谓词、端点、证据、置信度与实体解析。
  5. 构建 Snapshot完整 manifest；新图仍对查询不可见。
  6. Stage + Verify计数、ID、证据和 pipeline signature 全量核验。
  7. 原子切换ACTIVE_SNAPSHOT 与 ACTIVE_VERSION 同事务发布。
  8. 推进 Revisioncorpus revision +1；旧 embedding generation 变 stale。

权限内混合检索

系统先圈定授权集合再排序。Vector、BM25、图扩展、邻接补全与最终 hydrate 都携带同一 tenant / ACL / version / policy guard。

RRF k=60 · RA candidates · bounded context
  1. 服务端 Query Embedding客户端不能传 vector 或 embedding-space identity。
  2. 捕获语料身份tenant corpus revision + active embedding generation。
  3. 双路授权召回授权集合内 exact cosine；分区 BM25 后再次 ACL 校验。
  4. 标准 RRF按 Σ 1/(60+rank) 融合，不引入私有评分公式。
  5. 选择 Seeds稳定排序与固定候选上界。
  6. 图候选扩展仅经 accepted Entity；RA = Σ 1/degree。
  7. 重排与门控精确 cosine + 二次 RRF；确定性 relevance gate。
  8. 去重与邻接同版本内容去重，补相邻 Chunk，不越过 ACL。
  9. 上下文预算限制 Chunk 数、字符数、扩展深度与候选量。
  10. 重授权输出hydrate 精确来源并重读语料身份；变化则丢弃重试一次。
安全优先不是“全库 ANN 后过滤”；高分无权结果不会占据授权候选窗口或泄露存在性。
一致性Neo4j read-committed 下检测 revision/generation 改变；第二次变化直接 fail closed。

Grounded Answer Generation

模型只提交结构化回答计划；Citation、provenance 和最终文本由服务器验证并生成，模型不能伪造来源。

answered · conflict · insufficient_context
  1. 接收授权 Chunks生成模块不再自行查询 Neo4j，也不做新的权限决策。
  2. 完整性校验文本、绝对范围、checksum、文档版本与 provenance。
  3. 分配来源标签按检索顺序生成 S1 / S2；标签仅在本次请求有效。
  4. 版本化 Prompt只放源文本与 provenance，不放图事实或检索分数。
  5. 模型返回计划严格 schema：status、claims、source labels、quotes。
  6. Quote 定位每段 quote 必须在对应 Chunk 中唯一出现。
  7. Claim 支持校验限定词、否定、条件、模态与局部绑定都必须一致。
  8. 字面量保真数字、日期、币种与单位保持原样；冲突需多个来源。
  9. 服务端 Citation把可信 S 标签映射到真实文档、版本、Chunk 与坐标。
  10. 渲染或拒答非法输出安全拒答；provider 异常保留真实错误语义。
默认拒答空上下文直接 insufficient_context；无引用的实质性 Claim 不允许进入答案。
有限推理仅允许可本地重算的财年数值增减比较，并显式标记 Inference:。
硬上限10 Chunks、20k 上下文字符、20 Claims、每 Claim 5 Citations，问题 2k 字符。

06 / 10

安全、可靠性与可观测性：控制必须发生在边界内

系统避免“查完再过滤”“超时就释放容量”“模型说有引用就相信”等常见失效模式。每项保护都有明确实现位置与自动化负例。

ID

固定算法 JWT

HS256 签名、issuer、audience、exp、iat、subject、tenant、groups、scope、生命周期和大小全部校验。

ACL

查询内授权

Vector、BM25、图扩展、邻接与 hydrate 均在数据库查询内绑定 tenant、group、policy 和活动版本。

≤

有界执行

固定 worker + queue、每操作 deadline、过载快速失败；超时线程真正结束前不归还 capacity permit。

↻

谨慎重试

API 仅重试 provider-free 无副作用读取；写、检索和回答不在入口层盲目重放 provider 或事务。

LOG

默认不记内容

结构化日志使用字段白名单，递归脱敏 JWT、secret、URI userinfo 与控制字符；不记录问题和原文。

MET

低基数指标

记录 route、stage、error、延迟、token 与估算成本；不以 tenant、principal、document、query 作标签。

CAS

发布一致性

TenantCorpusState 与文档锁、预期 Snapshot CAS、manifest 校验、revision/generation 守卫。

DEL

删除不可复活

Tombstone generation 与 fencing token 阻断迟到 worker；目标记录原子删除，其他租户指纹保持不变。

ERR

可预测失败

稳定错误分类、脱敏响应、request/trace ID、no-store 与 nosniff，依赖异常不伪装。

08 / 10

优点与局限：它把正确性放在便利性之前

这套设计适合作为严谨系统的基线，但它也主动选择了保守实体解析、精确授权向量计算和严格模型输出校验，因此换来了复杂度与扩展成本。

优势

  • 证据完整：回答可回溯到不可变文档版本和精确 Chunk 坐标。
  • 读写隔离：原子 Snapshot 发布，不暴露半完成抽取结果。
  • 权限前置：ACL 进入每条 recall / expansion 查询，不靠末端过滤。
  • 标准算法：RRF 与 RA 透明、可复算，没有未经评估的私有权重。
  • 图证据分工：图负责导航，Chunk 承担事实，降低抽取幻觉传播。
  • 模型受约束：输出 schema、quote、claim、字面量、citation 全部二次验证。
  • 失败有界：幂等、lease fencing、tombstone、并发与重试语义明确。
  • 验证可审计：数据、模型、prompt、索引、镜像、配置和报告均版本绑定。

局限与技术债

  • Provider 真实性：确定性 reference 未覆盖真实 LLM/embedding 的质量、配额、费用和隐私。
  • 语料代表性：合成英文公司文档不能代表 OCR、表格、多语言与客户长尾分布。
  • 规模外推：单 Neo4j Community、五分钟负载，不代表集群和数天 soak。
  • 向量性能：授权集合内 exact cosine 安全但在更大规模可能成为瓶颈。
  • 摄取拓扑：HTTP 摄取同步终态；缺少外部 durable queue、对象存储和 worker 编排。
  • 语义校验：保守词法/局部规则不是通用 entailment proof，可能误拒或漏掉复杂支持。
  • 实体解析：当前是审计友好的 pairwise 决策，没有候选生成系统与审核 UI。
  • 部署工程：共享限流、非对称身份、密钥轮换、TLS、告警和 IaC 仍由目标环境补齐。
Trade-off 01Exact cosine vs ANN

当前优先保证授权候选不会被全库 ANN 窗口挤出。若改 ANN，必须证明过滤在候选窗口之前生效。

Trade-off 02Conservative ER vs recall

只有相同权威 ID 自动合并；名称重合进入人工复核。减少误合并，但增加治理工作量。

Trade-off 03Strict grounding vs answer rate

无法唯一定位 Quote 或保持限定词/数值时宁可拒答；可信度提高，回答覆盖率可能下降。

最小术语表

Snapshot
某文档版本在固定 pipeline 与治理策略下的完整派生图输出；验证后原子发布。
Corpus revision
租户活动语料状态的单调版本；用于发现查询期间的发布或撤权变化。
Embedding generation
同一向量空间的一组完整活动 Chunk embeddings；覆盖率 100% 后才能激活。
RRF
Reciprocal Rank Fusion；只依赖各通道排名，默认常数 k=60。
RA
Resource Allocation；共享低度数 Entity 对候选贡献更大，仅用于图候选扩展。
Fail closed
输入、授权、状态或证据无法确认时拒绝继续，而不是猜测、降级放行或输出部分结果。
