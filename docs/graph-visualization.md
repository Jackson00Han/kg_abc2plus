# 已发布图谱可视化制品

图谱探索将图谱生成与界面呈现分开：服务端从当前已发布、经过权限与精确证据校验的视图生成 JSON 布局文件，浏览器用同一套 Cytoscape 组件读取固定坐标。刷新、切换窗口宽度和全屏只改变视口，不重新运行力导向布局。此过程不导入知识、不修改发布版本、不补造关系。

设计参考上传的 `new_files/build_graph.py`、`new_files/render_graph.py` 所体现的“构建与呈现分离”，以及 `new_files/ai_copyright_graph.html` 的交互图谱展示。参考文件仅用于分析，未执行其导入或物化流程。

## 呈现方案与选择依据

调研了 [Sigma.js 的数据与坐标模型](https://www.sigmajs.org/docs/advanced/data/)、[AntV G6 的布局机制](https://g6.antv.antgroup.com/en/manual/layout/overview) 和 [Cytoscape 的预计算方案](https://blog.js.cytoscape.org/2020/05/11/layouts/)。结合当前项目已固定的 Cytoscape 依赖、带方向的关系、多来源事实和证据交互，选择继续使用 Cytoscape，将计算从浏览器移到服务端。没有为了更换外观再引入第二套图库。

采用“版本化 JSON 展示制品 + 通用渲染模板”，而非把原文与令牌嵌入独立 HTML。HTML 模板和样式随应用交付，布局坐标随知识发布保存。此选择保留权限即时复核与原有证据接口，也避免任意文本注入脚本和跨来源文件混用。

页面使用深色画布、稳定类型配色、关系网络与类型分组两个已保存布局。总览时采用圆点与有限关键节点标签；放大后显示实体卡片。视觉密度变化只改变图形和文字，不改变后端坐标。路径名称使用能区分当前节点的最短末段，完整名称与稳定 ID 仍保留在搜索、悬停和来源详情中。

图例可按类型筛选，搜索定位当前范围的节点，点选时突出一跳关联并打开相邻来源面板。缩放、拖拽、全屏、PNG 导出与键盘操作保持可用；分组底板不进入节点统计。本体与实例视图分别说明语义，图谱探索不分页。证据接口明确返回会话或可见范围失效时，页面清除旧图谱和旧详情。

探索页请求 `result_mode: "overview"`，一次返回当前授权筛选范围内全部节点与聚合关系，包括孤立节点；不返回属性记录，不受事实记录 `page_size` 影响，也不接受游标。桌面展示预算由 `desktop-graph.v1` 明确为最多 200 节点、300 关系；超限仍明确失败并提示调整展示范围，不返回截断图谱。普通图谱分页仍最多 200 项，字面量每页最多 200 项，不随总览关系预算一起放大。属性与来源通过「打开实体档案」按需读取。原有默认 `graph` 模式仍保留分页，供实体档案等调用方读取属性；游标排序保持版本校验。

## 生成与加载

1. `Neo4jKnowledgePublicationService.publish()` 或 `rollback()` 提交成功后触发 `on_activated`。预览不会触发。8002 运行入口为这一回调接入有界生成队列，使用服务端登记的知识库管理员与用户身份，分别生成两种来源等级视图。
2. 队列只有一个工作线程，最多容纳 4 项任务，每项最多 2 个权限身份。生成在发布事务之外执行，失败不会把已经提交的发布误报为失败。过期任务发现当前发布已改变即停止该版本的预热。
3. 启动时对当前可见知识库的已发布版本做一次补建。这是现有知识的只读迁移；不读取隔离知识库，不创建或切换任何发布。
4. `POST /v1/knowledge/graph:query` 保留原有认证、租户、来源权限、发布 pin、证据校验和分页契约，在响应中附加 `visualization`。服务端读取匹配 JSON 制品，仅返回响应中节点的坐标；本体坐标只对应响应中的本体类型。筛选和节点邻域使用完整授权视图的同一套坐标。
5. 新的来源筛选或权限组合，以及损坏或被清理的缓存，在首次授权访问时补建一次。之后刷新读取相同文件。布局版本升级生成新文件，旧文件不会就地改写为新版本。

默认文件目录是 `.local/graph-visualizations/`，可由服务端环境变量 `GRAPH_VISUALIZATION_DIR` 指定。目录不挂载到 HTTP 静态服务；文件名只包含服务端计算的摘要，用户不能提交路径。临时文件权限为 `0600`，写入后原子替换，文件校验失败会重建。制品只有稳定节点 ID、类型组、坐标、布局版本与生成时间，不包含来源原文、证据摘录、访问令牌或凭据。

制品键绑定租户、权限组、发布 ID、本体校验和、来源等级、版本筛选、授权视图摘要和布局输入。同一发布的不同权限范围不会共享输出文件。制品不能代替权限判断：每次图谱与证据读取仍通过原有查询复核 ACL 与发布状态，权限撤销后旧文件也不能被直接读取。

## 通用布局与依赖

后端模块为 `src/graphrag_prod/graph/visualization.py`，布局入口为同目录 `layout.cjs`。后者直接复用项目已固定版本的 Cytoscape.js 3.34.2 包，无 CDN、额外 npm 安装或新 Python 依赖；运行环境需要 Node.js 18 或更高版本。入口校验 Node.js 与 Cytoscape 版本，使用标准输入输出传递结构化 JSON，不拼接 shell 命令，且不给子进程传递服务凭据。

两种布局都预先生成，实例图谱与本体图谱分别保存：

- `network`：对连通分量运行 Cytoscape CoSE，固定初始坐标与随机种子，采用固定迭代上限，再进行卡片避碰和分量排布。孤立节点按类型分块，不会堆叠成纵向长列。
- `grouped`：按本体实体类型分块，块内使用网格，块间按照固定桌面比例排布。分组底板只表示视觉分类，不产生实体或关系事实。

实体卡片的布局间距约为 192 × 96；类型来自本体，无母线槽、水泵或项目名称的特殊分支。超过 300 个节点的完整视图使用确定性的类型网格作为网络布局的有界退化形式，并通过 `engine: bounded-type-grid.v1` 明确记录。节点与边的完整布局输入各不超过 20,000 项；输入不超过 8 MB，制品不超过 16 MB；单次子进程限时 20 秒，Node.js 堆上限 192 MB，应用内最多同时运行一个布局子进程。等待生成锁也有 20 秒上限。

依据：[Cytoscape 官方布局文档](https://js.cytoscape.org/#layouts)、[CoSE 参数](https://js.cytoscape.org/#layouts/cose)、[官方对预计算与缓存布局的说明](https://blog.js.cytoscape.org/2020/05/11/layouts/)。布局是呈现算法，不做诊断、权威等级推断或自定义知识评分。

## 响应扩展

`visualization` 的主要字段如下；实例节点坐标键为 `n:<entity_id>`，本体类型坐标键为 `t:<type_name>`。

```json
{
  "schema_version": "graph-visualization.v1",
  "layout_version": "cytoscape-3.34.2-cose-type-grid.v1",
  "artifact_id": "sha256 digest",
  "generated_at": "ISO 8601 UTC timestamp",
  "status": "READY",
  "default_layout": "network",
  "layouts": {
    "network": {"positions": {}, "groups": [], "engine": "cytoscape-3.34.2-cose-pack.v1"},
    "grouped": {"positions": {}, "groups": [], "engine": "type-grid-pack.v1"}
  },
  "ontology": {
    "network": {"positions": {}, "groups": [], "engine": "cytoscape-3.34.2-cose-pack.v1"},
    "grouped": {"positions": {}, "groups": [], "engine": "type-grid-pack.v1"}
  }
}
```

类型组包含 `type, x, y, width, height, count`；坐标和宽高使用图谱空间，`x,y` 是组底板左上角。节点的 `x,y` 是卡片中心。`count` 在响应中裁剪为当页节点数量。不得把分组底板当成图谱节点参与统计。
