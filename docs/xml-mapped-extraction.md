# XML 声明式候选构建

`construction/xml_executor.py` 将用户明确提供的 `xml-declarative-mapping:v1` 配置接入既有候选校验与治理。映射先对完整 XML 做类型、属性、复合身份、端点与字段覆盖预检，再通过严格候选校验器形成输出；不调用抽取模型，不读取既有实例制品。XML 嵌套只按配置指定的归属关系解释，工程连接仅取显式引用，不产生运行事件。

当前接口为 `XmlMappingExtractor(base, parsed, mapping_profile)`：`prepare_document(read, persist, before_model_call)` 保存来源、本体、映射及预检校验和和待定项；`extract_audited(...)` 产生候选；`summary()` 返回覆盖情况和未完成语义。`deterministic_batches=True`、`max_document_model_calls=0`，模型更换不改变确定性映射请求身份。跨文档仍按文档、本体、映射标识和来源复合身份隔离，不能按显示名称合并。

当前持久化证据契约要求同一 Chunk 内包含断言端点。因此该适配器要求一个覆盖完整、未改写 XML 的证据 Chunk，最大 65,536 字符。关系证据取真实源端点、目标端点和引用标记的最小连续原文范围；属性证据取真实对象标识与属性值之间的原文。全量位置校验、租户和源码校验和仍执行。超限明确失败，不截断证据或静默遗漏关系。这个证据窗口与模型上下文及嵌入输入预算分别管理，调用方负责嵌入和存储的版本化处理。

独立确定性预算为最多 500 实体、1,000 关系、1,000 属性、总计 1,000 个 ABox 记录、2,000,000 字符候选载荷。不会提高外部模型输出或请求预算。预检中的任意错误、未处置字段或未解析的实际引用阻断构建；配置中明确声明的延后关系保留原因，不补造端点。

直接复制属性保留精确原文，数量只拆分原文明确携带的数值和单位。当前 TypedLiteralValue 持久化契约尚不能证明有限枚举语义转换，因此非必填枚举转换保留在版本化映射审计中，标记 `XML_ENUM_LITERAL_PROOF_REQUIRED`，不伪装成原文直接包含规范值。必填枚举不具备可持久化证明时阻断。转义后的 XML 属性值也不冒充原文；未来需要独立的编码/映射证明契约。
