### 3.1 必须先解决的具体不兼容

1. **本体源格式不兼容。** 包使用 `ai_power.busway.ontology@0.1.1` 的七节属性图定义；当前 [ontology/source.py](../src/graphrag_prod/ontology/source.py) 第 174 行起只接受 `ai_power.knowledge_ontology@1.0.0` 的十节契约及 `graph_native_property_graph/forward_only`。不能直接提交原 YAML 或嵌入的 ontology，也不能只改版本字符串。
2. **领域约束耦合。** [source_validation.py](../src/graphrag_prod/ontology/source_validation.py) 第 104 行起强制现象恰有一个 localization、所有 RootCause 都有 EVALUATED_BY。当前样例三相不平衡只有适用范围，五个原因概念均无规则绑定；这是合法的候选知识边界。应把这些要求迁入显式、版本化的领域约束配置，不为通过校验伪造范围或规则。第 27 行的跨项目实例关系一律拒绝，也需区分归属与有据连接；租户及 ACL 隔离保持不变。
3. **联合约束缺口。** 包的 `quantity_kind/canonical_unit/value_kind` 是合法三元组表。拆成三个独立 enum 会接受非法组合。补有界的通用联合属性约束，并为不支持的约束明确报错。当前已有类型继承，但不支持完整 OWL、互斥类型或任意约束交集，不应扩大宣传。
4. **权威导入不适用。** [knowledge/models.py](../src/graphrag_prod/knowledge/models.py) 第 627 行及 [knowledge/store.py](../src/graphrag_prod/knowledge/store.py) 第 718 行要求 `EXPERT_IMPORT + AUTHORITATIVE + PUBLISHED`。把本包套入该入口会改变模拟和未核验内容的含义；人工补充入口同样不能伪装成文档映射入口。
5. **证据不只是字段重命名。** `AssertionRecord` 当前一个主 EvidenceReference；ContextPropertyEvidence 仅支持特定同文档上下文值。现有关系端点还需处于同 Chunk、同断言范围。外包引用是路径和原值，其中 235 个 `raw_value` 为对象，不能 JSON 序列化后冒称原文摘录。
6. **展示配对与治理配对需一致。** 核心 RelationshipTypeDefinition 已支持显式类型对，但 [graph-model.mjs](../src/graphrag_prod/playground/static/industrial/graph-model.mjs) 第 184 行与 [visualization.py](../src/graphrag_prod/graph/visualization.py) 第 43 行仍按 source_types × target_types 生成模型边。应让展示使用同一允许类型对，避免画出本体不允许的组合。

## 4. 应沉淀的三组通用方法

### 4.1 本体优化：以问题、证据与版本影响驱动

本节保留后续通用方法方向。首期采用固定版本的 v11 本体，优先实现格式读取、约束支持和最小兼容检查，不要求先交付完整的本体优化器或提案工作台。

先确定本体需要回答的问题，例如“这是设备对象、一般概念还是事件”“候选原因的适用条件是什么”“测点采用的是何种语义、哪些条件未核验”“该关系由什么版本的资料支持”。以这些问题检查模型，不能以图是否连通、类型是否齐全或样例边数作为优化目标。

通用流程建议为：问题清单 → 概念/关系审校 → 约束检查 → 变更提案 → 影响分析 → 人工审核 → 新本体版本及受治理实例迁移。

每项提案记录原定义、新定义、来源位置、采用理由、冲突、不支持能力和影响对象。影响扫描覆盖映射、候选、已发布断言、事实身份、检索投影与展示 profile；改枚举、必填属性、端点、身份键或单位规范应说明是否破坏兼容。旧发布继续绑定旧 TBox，不能被新定义静默重解释。

从参考包提炼以下审校原则：

- 类型继承、概念分类、工程组成与物理连接分开；`SPECIALIZES` 概念关系不自动变成类型继承，`CONTAINS` 父→子不为适配遍历而反转正式边。
- 测点是采集位置或通道，观测量是语义概念；应该具备的测点不等于已安装/已绑定。
- 现象、候选原因、规则输出和运行事件分开；没有根因覆盖不等于现象不存在。
- 近义词不自动等价：宽泛相关性不等于某个回归指标，温差不等于温升，局部热点与“没有局部热点”不能合并。
- 关系用途从材料获得：辅助解释、规则判据、定位、比较与适用范围分别表达，不根据缺项自动填默认值。

LLM 可提出差异与候选，不能直接改激活本体或把自己的解释作为证据。第一期不建设任意表达式执行器、OWL 推理机或诊断引擎。

### 4.2 可信实例构建：来源、映射、陈述共同受治理

复用现有 `construction → knowledge → publication` 流程，增加一个明确的确定性映射候选入口：

1. 登记获授权来源和派生关系，固定原始字节、版本、哈希与定位方式；上游缺失明确记录。
2. 文档稳定章节/字段形成覆盖清单，每项采用、候选、拒绝或不抽取均有理由。对于配置声明的闭合章节集合，新增未处理项阻断完成；普通开放文档不能被伪称实现了完整章节覆盖。
3. 映射决定身份、类型、引用和转译，业务值仍读取原文；保存映射版本、哈希和审校记录。
4. 类型、属性、关系、关系属性分别生成候选陈述与证据；真实性限制和身份映射作为必要支持项保留。
5. 依次执行身份、类型/端点/联合属性、引用原文、语境、冲突与覆盖检查；结构一致、重建一致和工业真实性分别报告。
6. 进入已有身份与语义审核、发布预览和发布流程；外部采纳记录只作为审核输入。

原有 16 个候选测点进入独立处置队列，不生成正式 OBSERVES。教学 CASE 不生成设备事件。后续取得真实资料时新增版本和证据，逐条重新审校；不能把模拟状态改名为真实。

包内 `input/diagnostic-package/build.py`、`input/diagnostic-package/scripts/validate_merged.py` 的章节定位、显式映射、覆盖与反例校验可作实现参考，但不作为平台运行入口。PH/RC/PC 等前缀、19/15/15 数量、固定裁剪 ID、设备类型码和关系白名单归领域包配置或样例验收。

### 4.3 3D 展示：事实、投影、布局与交互分离

复用 `spatial-layout.js` 的确定性分簇/三维避碰和 `renderer-3d.js` 的渲染机制；保留平台私有制品、服务端授权和按需证据读取。建议保留二维模式，三维作为同一授权图的可选阅读方式。

- 总览、工程、知识三个视图来自同一事实快照；本体视图来自声明，不能计入实例数量。
- 工程包含、归属、连接、观测、知识关系角色由版本化 view profile 配置；方向明确，未知已声明类型进入通用分组。包中部分 layout 配置字段只是描述，不能宣称改配置就支持任意算法。
- 基础 xyz 布局在服务端受限计算并保存；筛选复用当前授权范围与版本的坐标。会话偏移、D3 速度、浮动、相机状态独立，不写入业务属性或证据。
- D3 使用克隆节点/边，单一动画循环；只对当前可见连通分量求解，手动固定点受保护，释放保留速度并冷却。单连通图可能全部参与，必须另设受力预算。
- 悬停与选择分离，屏幕平面拖点、鼠标锚点旋转、独立浮动/弹性开关、减少动态偏好、后台停止与销毁可复用。固定参数只作起点，不解释成物理量或因果强度。
- 证据和候选面板用平台组件重新接线，不复制全量旁索引或将 `snapshot_path` 暴露成任意文件读取路径。

## 5. 契约适配方案

以下是拟议的版本化契约职责和字段，不代表已创建 Schema 或可调用的新接口。

### 5.1 分开管理六类制品

| 制品 | 职责 | 关键内容 |
| --- | --- | --- |
| 本体定义 | 定义合法知识表达 | 类型、属性、允许类型对、身份约束、通用有限约束；原始与编译后哈希分开 |
| 导入映射 | 适配具体来源格式 | 解析器、选择器、稳定身份、字段、单位表达、关系方向、证据定位、覆盖处置 |
| 知识包清单 | 装配受版本约束的文件 | package ID/version、文件白名单/角色/哈希、各契约版本、适配器版本、依赖、排除策略 |
| 候选与语义审校记录 | 管理采用决定 | 外部陈述 ID、平台 revision、理由、冲突/缺项、审校主体和映射依据 |
| 证据与声明语境 | 保留证明能力和边界 | 多证据角色、来源派生链、模拟/配置/事件边界、适用条件与可得性 |
| 展示 profile 与布局制品 | 组织阅读 | 类型分组、关系角色/方向、投影/布局版本、xyz、展示路径与预算状态 |

本体不依赖固定项目、文件清单和样例数量；知识包引用本体，映射引用两者，展示消费受治理结果。清单必须区分当前实例入口、当前陈述实际依赖的证据来源、仅登记的历史追溯项；文件位于 `merged/` 内不意味着可以递归摄取为当前知识。

### 5.2 参考字段到平台字段

| 参考契约 | 目标处理 |
| --- | --- |
| `exchange_version` 等各版本 | 分别验证；未知版本/不支持约束明确拒绝，禁止静默丢字段 |
| `ontology` | 显式旧格式适配器 → 平台 TBox；逐约束报告原生支持、转换实现或不支持 |
| `entities[].properties.entity_id` | 外部 namespace + ID → tenant/type/canonical_key → 平台稳定 entity_id；保留不可变对照 |
| 类型、实体属性、关系、关系属性陈述 | 分别映射 mention/type 证明、literal assertion、关系断言和关系属性；不要求外部陈述数等于内部 record 数 |
| `relation ID / statement_id / evidence_id` | 分别保留外部身份对照；平台关系继续用 fact_key 聚合，多来源 revision 不丢失 |
| `origin=mapped/extracted` | 保留外部形成说明；经适配器确定实际形成方式。确定性解析不能伪称 LLM_EXTRACTED 或 RULE_DERIVED |
| `accepted_configuration/project_definition/accepted_simulation` | 保存为 external_adoption_status；初次接入生成 CANDIDATE，平台审核与发布独立 |
| 来源 `role/authority_basis` | 保存为上游来源声明；权威性按平台受治理来源记录判定，外部包文字不授予操作权限 |
| `evidence_ids[]` | 转为有角色的支持证据集合，每项绑定真实文档版本、Chunk、范围、哈希和 ACL |
| `context` | 拆为声明语义、真实性边界与审核/展示信息；不把所有内容塞进业务属性或不透明 JSON |
| `criterion_role/scope_role` | 经本体约束进入关系属性，保留逐条来源，不补造缺失值 |
| `point_resolution` | 独立处置候选与采用范围；配置采用不升级为运行绑定或读数 |
| `publication-policy/removed-content-report` | 当前包范围与差异预览依据，不是删除平台数据的指令 |

保留 `sim:` 外部身份空间；名称、来源哈希或数组顺序不作为实体身份。同一语义在证据更新后延续身份，类型或身份键改变需迁移提案。适用范围、时间、条件等影响事实含义的字段纳入规范化事实区分；审核状态、来源等级、展示分组不应全部哈希进 fact_key。

### 5.3 多证据与模拟语义

在保留现有 EvidenceReference 精确校验的基础上，增加有界的支持集合，区分直接陈述、身份映射、语义映射、范围/真实性限制、派生追溯。不能简单移除“端点同 Chunk”检查；跨文档映射使用专门的证明模型，逐项验证源提及、目标身份、映射版本和适用边界。单证据旧记录继续按旧版本严格读取。

定位适配必须把 XML/YAML/Markdown/JSON 路径回放到实际原文范围，同时保存原始字节与规范化文本之间的定位关系。不能把交换文件重新分块后称为原始工业依据，也不能用拼接的摘录伪造连续 Chunk。

一个支持集合的必要边界证据必须全部可读；若存在多个独立支持集合，至少有一个完整且获授权的集合才能支持该断言。其他受限支持不能泄露在计数、摘要或来源数组中。同一派生链不能通过重复登记提升来源等级或独立证据数量。

新增确定性形成方式与候选写入策略时保留现有 origin/authority 合法组合；对新方式明确规定由什么受治理来源记录决定 authority。不要批量重标记旧数据。新增独立声明语境，至少承载：

```text
external_adoption_status
content_layer / simulation 标记
claim_scope / industrial_validation / runtime_event
upstream_business_document 可得性
必要的适用条件、未核验项与支持证据引用
```

`baseline_knowledge` 是此包的相对来源标签，不能成为通用权威等级。节点 mixed 状态由它自己的已授权陈述计算；邻接模拟关系不改变节点原有来源，非模拟端点也不提升模拟边。新输入缺失必要真实性边界时拒绝或隔离；`UNKNOWN/unclassified` 不默认视为真实。旧记录按明确的版本兼容策略读取，不批量重标为真实。

正常事实回答默认排除模拟，获授权的演示/模拟请求才显式纳入。不能仅映射成 `FIXTURE + SECONDARY`：现有默认检索包含已发布 SECONDARY。此策略需进入召回候选、图扩展、邻近 Chunk 补全、统计、来源/证据读取和缓存，而不只在前端隐藏。对混合文档采用受治理的段落/陈述可用范围，不能因只有一条真实陈述就向模型暴露整段模拟内容。返回与生成契约继续携带相应标记；当前 [generation/prompt.py](../src/graphrag_prod/generation/prompt.py) 第 45 行仅区分 HUMAN_RECORD/DOCUMENT，尚不能承担这项要求。

### 5.4 复用现有 API 与发布机制

| 现有边界 | 适配方式 |
| --- | --- |
| `/v1/ontologies:import`、TBox publish | 在受限格式适配后复用；补影响分析，不直接激活外部定义 |
| `/v1/knowledge:preflight`、`:construct` | 为新格式显式版本化请求，或增加薄的包预检/候选适配入口；下游继续使用同一构建与治理服务 |
| 身份、review-queue、reviews:batch | 增加映射、覆盖、语义边界和支持证据的审校信息 |
| publications:preview / :publish | 保留明确 revision 集合、expected active publication、preview hash、完整性和索引校验 |
| graph:query / graph:evidence | 在相同授权 pin 和 view_token 上扩展投影，证据按需读取 |
| sources:query / sources:read | 扩展结构化定位；来源和计数继续受权限过滤 |
| retrieval / answers | 补服务端内容范围策略与引用语境；不改变知识层和 DeerFlow/诊断层责任 |

请求中的 tenant、principal、groups 不从包或 Agent 自报字段采信，仍由服务端认证确定。package/project/knowledge-base ID 分开，外部对象映射不授予跨项目访问权限。预检为只读，应用候选与发布分别是有权限约束的操作。

包更新的撤回建议只针对该包映射的来源贡献。其他来源仍支持的对象不删除；历史证据保留。v11 排除清单随包版本进入预检与差异检查，避免未来从归档重建时重新引入已排除内容，但不自动更改平台发布。

当前 `graphrag-abox-export-v1` 是已发布快照与证据引用导出，不含完整源文、本体和审核历史，也没有直接重导入能力；它可作为适配对照，不能充当候选导入契约或完整备份。

### 5.5 3D 投影契约

保留现有 `nodes/edges/pin/view_token` 及多来源 `fact_key/revision_ids/sources`。在新的展示契约版本中增加 dimension、xyz、projection/layout/profile 版本及哈希、视图、警告、预算和完整性状态；旧 `graph-visualization.v1` 的二维消费者保持兼容。

正式关系与展示关系分开：

| 展示关系种类 | 约束 |
| --- | --- |
| fact | 对应平台聚合事实及全部获授权、符合内容策略且必要证明完整的支持 revision |
| path_summary | 仅折叠配置允许的真实路径，保留原 fact/revision、中间节点、方向和末端谓词 |
| ontology_allowance | 从本体真实允许类型对生成，无伪造实例陈述，不计入实例关系 |

路径汇总只有在两端、中间点和全部原边均处于同一授权快照时才能生成。“隐藏节点”只能是界面折叠，不能是无权节点。展开继续携带同一 pin/view_token 并受预算限制。汇总不写入知识图、不进入检索事实，也不变成直接断言证据；它与平台 RULE_DERIVED 含义不同。

来源筛选先作用于获授权陈述，再重算聚合关系、来源数组、内容层和路径计数；`baseline-only` 不映射成 `AUTHORITATIVE_ONLY`。同一 fact_key 同时有真实与模拟支持时，符合策略的真实支持可使事实返回，但不能同时放行被排除的模拟正文、来源计数或不完整支持集合。缓存键沿用 tenant、授权范围、发布/本体、trust policy、版本筛选和视图摘要，再加入内容策略、projection/profile/layout 版本。制品继续私有存储，不包含原文、访问 token 或全量 evidence 索引；每次读取仍复核权限。

## 8. 预算、验证与实施风险

### 8.1 先明确预算实际来源

当前 [browse_models.py](../src/graphrag_prod/graph/browse_models.py) 第 12 行起和 API 响应限制总览 150 节点、200 边；参考合并图 192/268、仅基线 172/219 都超限。初期按来源或邻域缩小范围；需要完整样例时单独评审读取、投影、传输、渲染和受力预算，不能只提高画布上限。

发现配置口径存在差异：[workbench-construction.v2.json](../contracts/profiles/workbench-construction.v2.json) 中发布变更/清单仍写 500/2,000，[publication_guard.py](../src/graphrag_prod/knowledge/publication_guard.py) 的执行常量却为 20,000/20,000（选择上限 10,000）。运行脚本会读取该 profile，但不能因此推定其全部字段都控制发布。P0 应核对实际调用链并统一版本化口径，不以此分析替代运行实测，也不为迁就样例放宽限制。

既有布局的 20,000 输入项上限、20 秒子进程及有界网格降级，不代表浏览器能显示同等规模。参考 LOD 主要控制标签，不是分块流式加载。后续分别记录证据复核、冷/热加载、首次可交互、帧时、内存与受力耗时；大连通分量超限时停止弹性并明确说明，保留静态阅读/二维回退。

### 8.2 必要的验证集

- **契约与语义**：未知约束不丢弃、离散允许类型对不笛卡尔展开、合法/非法联合值、关系方向、归属与连接项目边界、类型模板不实例化、同名不同义、证据版本变化不漂移实体身份。
- **构建与证据**：逐条位置回放、映射修改后的重审、遗漏章节、重复身份、候选/采纳矛盾、源文件损坏、丢失真实性边界、幂等重放、批次依赖闭合、撤回后其他来源支持仍保留。
- **治理与读取**：发布预览哈希/CAS、旧 TBox 绑定、跨租户与跨 ACL、必要支持证据不可见、模拟召回和邻块泄露、受限来源计数、权限变化后的 token/缓存失效、失败不暴露半个快照。涉及查询/事务/持久化时必须使用真实 Neo4j 隔离夹具验证，不能只有模型单测。
- **通用性**：水泵与母线槽配置互换、第三工程、改名、数组重排、新声明类型、孤立概念及空候选集合；临时纯结构夹具验证算法，不恢复其他工业语料。
- **桌面浏览器**：真实 8002、pump-only、独立上下文、只读白名单；1280/1440/1920、滚动和全屏，实际查看截图。覆盖证据/弹窗、筛选组合、汇总展开、旋转锚点、拖动冷却/再抓、后台、恢复布局、WebGL/Canvas 与减少动态偏好；存在两个可访问版本时检查真实历史比较及关闭，不执行切换。CUA 首次连接失败后按项目约定改用独立 Playwright Chromium 并排查启动依赖。

### 8.3 本轮证据能支持的结论
