# Industrial 工作台迁移方案

## 目标与边界

以 `/industrial` 为唯一操作入口，保留 Industrial 的侧栏、配色、布局和来源卡片，接入原工作台已经完成的治理能力。迁移页面与功能，不合并两个服务各自的本地数据库，不重置既有资料、身份、证据或发布历史。

## 页面与功能对应

| 页面 | 迁移后的内容 |
| --- | --- |
| 知识构建 | 顶部折叠“专家基准与本体”：本体查看、校验、导出、复制下一版本、保存启用，以及专家实例 JSON 导入。日常主流程为上传资料、复核候选、发布知识；可选择权威基准或业务资料，保留各自来源等级。 |
| 复核候选 | 保留实体消歧、目标选择、规范化编辑、原文段落/上下文/全文、确认并追加来源、作为独立事实确认、不采纳、暂缓、人工补充与批量操作。 |
| 发布知识 | 按实体选择候选来源、返回修改、完整增删改预览、并发版本校验、定位发布阻塞；发布后刷新图谱和来源。 |
| 图谱探索 | 实际已发布实例为默认视图；保留本体视图、权限范围、分页、证据定位与导出。增加网络/层级布局、节点搜索、邻域高亮、聚焦、标签切换、缩放和全屏。相同事实聚合来源，人工独立事实保持可区分。 |
| 实体档案 | 从图谱入口打开；完整属性、关系、来源分页与维护动作继续可用。 |
| 证据检索 | 保留现有窗口和检索链路，返回原文上下文、文档版本与精确引用；不调用最终答案生成。 |
| 来源资料 | 展示当前身份可读的全部原始文档，包括新上传的通用资料；按文档版本读取原文并分页，保留工业资料的适用范围。 |
| 质量与维护 | 侧栏底部轻入口：质量检查与历史报告、人工核查、知识清单与修订、来源撤回、发布比较与回滚。 |

## 实施顺序

1. 提取成熟治理代码为独立模块与模板，接入 Industrial 的当前身份、会话和请求取消机制。
2. 完成构建布局、专家折叠区、三步切换与维护入口，保留完整审核和发布细节。
3. 整合所有原始来源和检索范围；扩展图谱交互并接实体档案。
4. 删除旧工作台页面内容及回链，旧页面地址转向 Industrial；共享接口保持兼容。
5. 运行相关确定性轻量检查、模块语法和差异检查，启动页面核对交互与布局。记录实际通过项及未覆盖范围。

## 不变的约束

- 页面身份由用户明确选择，不能自动切换为管理员。
- 权威来源、业务来源和人工补充分别保留，确认操作不提升来源等级。
- 发布使用完整预览和当前版本校验；重复事实聚合证据，人工判定独立必须保留原因。
- 各查询、计数、证据和分页继续执行租户与访问权限过滤。
- 所有破坏性维护继续使用既有可审计流程；开发环境“全部清空”不作为正式页面的日常功能。后续新增的[当前项目重置](project-knowledge-bases.md)采用隔离归档，不清空整个数据库。
- 根据本地 Codex 用量事件监测用户指定额度，剩余达到 45% 时立即停止，等待新指令。

## 实施与验证记录

2026-09-10 已完成第一版迁移，8002 服务已按原配置重启，保留已有数据库。

- 原工作台 HTML 已删除，`/` 与 `/playground` 转向 `/industrial`，侧栏移除旧服务台回链。
- 治理实现提取为 `governance.mjs`、独立模板与样式；完整使用 Industrial 当前身份。专家区、三步构建、实体档案和维护区已接线。
- 支持无产品分类的通用文档与自定义本体；显式选择工业产品族时仍使用原工业约束与检索。两个检索引擎共用同一嵌入空间，沿用存储层空间/维度检查。
- 关系重复聚合、独立事实确认、发布预览和历史维护均保留。实体档案返回主图谱，原文打开统一来源弹窗。
