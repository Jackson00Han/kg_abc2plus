# 项目知识库、身份与重置

2026-09-10：8002 Industrial 工作台新增项目选择、新建独立知识库、当前库重置；身份简化为管理员和用户。

## 使用

- 顶部“知识库”选择项目，旁边“身份”仅显示管理员、用户。切换项目会清除页面中前一个项目的图谱、检索结果、来源和未提交编辑。
- 管理员点击知识库旁的 `+` 新建并进入空白项目，从知识构建中的专家基准与本体开始。每个项目独立保存本体、原始文档、候选事实和发布历史。
- 用户可以检索、浏览图谱及有权访问的来源；管理员可以构建、审核、发布与维护。新库上传资料的访问组目前仅提供“假想的用户组-1”下拉选项，管理员默认可见。用户组管理记入 `to_do_list.md`，暂不实现。已有项目保留原访问组，角色简化不会扩大旧资料的公开范围。
- 管理员在侧栏底部“质量与维护”找到“重置当前知识库”，核对数据数量并输入当前库名后确认。运行中的上传、审核、发布等写入任务会阻止重置；页面自动读取图谱和资料不会阻止重置。其他项目不受影响。
- 重置后重新输入本体并上传资料即可从头搭建。旧窗口需要刷新；不会自动续签到新代次执行旧编辑。

## 数据边界与限制

项目注册信息持久化在 Neo4j 中。每个项目绑定独立的活动 `tenant_id`；所有业务接口沿用已有租户与访问组过滤，而非仅在页面筛选。项目名称和项目 ID 稳定，重置只切换活动租户代次，并建立独立、明确版本的嵌入索引。

重置是逻辑清空：不可变的原文、证据和审核历史隔离归档，旧租户不再获得工作台会话，也不再进入当前项目的浏览、检索或发布。它不物理删除数据库记录或回收磁盘空间，不提供历史归档恢复入口。服务重启不会恢复已重置的旧代次。

创建与重置带操作 UUID，重复请求保持幂等；重置同时检查项目名称、代次和当前管理员身份。数据库事务原子更新项目指针并记录操作者与旧代次。写入任务计数覆盖后台执行阶段，防止请求超时后仍在运行的工作与重置竞争。重置期间尚未完成的读取响应会因旧租户失效而被拒绝，不能返回旧库结果。

当前为本地单进程工作台：项目与角色选择属于本地测试身份，不是生产登录系统。项目数据隔离不等于不同真实用户之间的项目成员授权；可访问本地工作台的人可以选择已有项目身份。面向多人生产使用前，应接入真实登录、项目成员权限与服务端角色分配；多实例部署还需要分布式任务/重置协调。当前最多 100 个项目，归档与向量索引的容量清理需另行设计。

## 重置阻塞与弹窗修正
