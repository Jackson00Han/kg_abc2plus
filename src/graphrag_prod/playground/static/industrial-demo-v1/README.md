# 循环水泵知识构建体验包 v1

这是一套虚构的、本项目约定为专家基准的工业测试材料，不引用外部行业标准。
本体以现有工业资产模板为基础，限定到场所、设备、部件和风险；设备必须带有
STRING 类型的唯一 `EquipmentCode`，`RatedPower` 使用 DECIMAL 与 `kW`。

- `authoritative_source.txt`：初始权威来源台账；仅入库与向量化，无需模型抽取。
- `ontology.json`：可编辑、需人工导入并发布的本体定义。
- `authoritative_instances.template.json`：3 个专家实体、2 个关系、2 个属性事实，
  每条记录均有台账中的精确字符范围。占位 ID 必须由本次真实上传结果替换；
  仍需人工导入，并在第 05 区发布后成为活动权威知识。
- `maintenance_report.txt`：153 字符的单设备维护条目；设备名仅出现一次，
  后接设备编码、功率、部件与风险。同一设备编码和唯一部件别名便于匹配已发布
  权威实体，另提供“机械密封渗漏风险”这一新增候选实体与关系。
- `homonym_report.txt`：可选反例；同名“循环水泵”的设备编码为 `BC-P-202`，
  不应链接到编码为 `BC-P-101` 的权威设备。
- `manifest.json`：固定文件摘要、上传元数据、预期结果与演示检索问题。

三个文本文件分别小于 600 字符，默认每份只占一个 Chunk，不改变开发环境
资源上限。模型输出仍需实际检查；示例预期不是将模型结果替换成固定答案。
同名反例适合在主流程通过后单独上传，不必加入第一次发布。

当前身份匹配只使用绑定到当前提及 revision 的身份属性事实，不能把其他
提及的设备编码自动传播过来。因此长文中同一设备的其他提及可能返回身份缺失
冲突；必须保持分离，不能凭名称强行链接。本入门条目的简化没有放宽这条规则。

保留文件原始 UTF-8 字节与换行；修改后不能再使用原模板的精确证据绑定。
同一来源的专家导入使用稳定 `source_key` 和初始 revision 0，重复导入已成功的
批次不会被当作新知识静默追加。正常体验只需导入一次，再查看清单或发布历史。

离线校验命令：

```sh
uv run python -m unittest discover -s tests/unit -p 'test_industrial_demo.py' -v
```

校验覆盖摘要、默认切块、精确引文、API 契约、本体与属性类型，以及同名不同
设备编码不自动合并。它不调用 embedding 或 LLM，也不修改 Neo4j。
